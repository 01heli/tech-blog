## 你买的"交换机"可能根本不是交换机

这是一个真实的故事。

几年前我给家里组网，在淘宝搜"交换机"，买了一个 5 口的便宜货。插上电，网线一接，所有设备能上网——挺好。直到有一天，我想把家里的监控摄像头和 NAS 隔离开，才发现了问题：这台"交换机"上根本没有地方配置 VLAN，甚至没有登录界面。它就是一块铁盒子，插上就能用，但你想做任何定制——没门。

后来我才搞清楚：**我买的是一台"非网管二层交换机"**。名字里的三个词——非网管、二层、交换机——每个都有确切的技术含义，没有任何一个是在故弄玄虚。

这篇文章从最基础的地方出发，把这几个概念用你能理解的方式拆开。

## 第一部分：交换机能干什么——从一个"接网线"的故事讲起

### 互联网时代之前，局域网怎么通？

90 年代，办公室要联网，最常见的设备不是交换机，是**集线器（Hub）**。

Hub 的工作原理用一句话就能讲清：**从任意一个口收到的信号，原封不动从其他所有口复制出去。** 它不读内容，不管目标是谁，反正全发一遍。

```
你发一个数据帧给同事 Bob：
  PC-A ──→ Hub ──→ PC-B（Bob，目标）
                 ──→ PC-C（不相关的机器，也收到了）
                 ──→ PC-D（不相关的机器，也收到了）
```

这带来了两个致命问题：

**问题一：冲突域。** 所有连在 Hub 上的设备共享同一根"线"（严格说是同一个冲突域）。如果 PC-A 在发数据的同时 PC-B 也在发，两个信号会在 Hub 内部碰撞，双双报废。然后双方都要随机等待一段时间再重试。这就是经典的 **CSMA/CD**（载波侦听多路访问/冲突检测）——你插 10 台设备到一个 Hub，实际可用带宽可能连标称带宽的 30% 都不到。

**问题二：安全。** 你给 Bob 发的数据，Hub 复制给了所有人。任何人开一个抓包软件（Wireshark），在"混杂模式"下能抓到整个网络所有的通信——包括明文的密码。

### 交换机做了什么不同的事？

**交换机** 解决的就是 Hub 的"全发一遍"问题。它内部分析每一个到达的数据帧的**目标 MAC 地址**，然后**只从目标设备所在的那个端口转发出去**。

```
你发一个数据帧给同事 Bob：
  PC-A ──→ 交换机 ──→ PC-B（Bob，只有他收到）
                     PC-C（收不到）
                     PC-D（收不到）
```

就这一项改变，带来了：
- **没有冲突了**：每个端口有独立的冲突域，A→B 和 C→D 可以同时通信，不会碰撞。配合全双工（同时收发），冲突域彻底消失。
- **更安全了**：不相关的设备收不到不是发给自己的数据。虽然 ARP 广播还是会泛洪全部端口，但单播流量是私密的。
- **带宽利用效率高**：8 口千兆交换机在 4 对设备同时通信时，理论总吞吐量是 8 Gbps（全双工）。8 口千兆 Hub 在碰撞控制下可能连 300 Mbps 都跑不满。

## 第二部分：OSI 的"层"到底是什么意思

"二层交换机"这个说法来自 OSI 七层模型。你不用记住全部七层，只需要理解它的核心思想：**每一层只负责一件事，下层为上层提供服务，同层之间有自己的"语言"**。

```
┌──────────────────────────────────────────────────────┐
│ OSI 参考模型（简化版）                                  │
├─────┬────────────────────────────────────────────────┤
│ L7  │ 应用层    HTTP、DNS、SMTP……                     │
│ L4  │ 传输层    TCP（可靠）、UDP（快速）                │
│ L3  │ 网络层    IP 地址、路由选择、跨网络传输            │
│ L2  │ 数据链路层 MAC 地址、帧格式、局域网内点到点传输      │
│ L1  │ 物理层    电信号、光信号、线缆、无线射频            │
└─────┴────────────────────────────────────────────────┘
```

一个好记的类比：快递系统。

| OSI 层 | 对应快递中的角色 |
|--------|-----------------|
| L7 应用层 | 你写的信的内容和格式（中文/英文/Python 代码？） |
| L4 传输层 | 快递公司承诺"保价还是平邮"（可靠性保证） |
| **L3 网络层** | **收件人省/市 + 邮编**（IP 地址，跨城市分拣用） |
| **L2 数据链路层** | **收件人小区 + 门牌号**（MAC 地址，最后一公里用） |
| L1 物理层 | 快递卡车走哪条路、用什么速度（网线/光纤/WiFi） |

**一个数据包的"包装"过程**：

```
┌────────────────────────────────┐
│ L2 帧头（源 MAC + 目标 MAC）      │ ← 交换机读这个
├────────────────────────────────┤
│ L3 IP 头（源 IP + 目标 IP）      │ ← 路由器读这个
├────────────────────────────────┤
│ L4 TCP/UDP 头（端口号）          │
├────────────────────────────────┤
│ 应用数据（HTTP/JSON/图片……）     │
├────────────────────────────────┤
│ L2 帧尾（CRC 校验）              │
└────────────────────────────────┘
```

**这就是"二层交换机"名字的由来**：它只拆到 L2 的帧头，读取里面的源 MAC 和目标 MAC 来决定转发行为，对 L3 及以上的 IP 地址、TCP 端口号一概不知。

同理，**三层交换机**就是能拆到 L3 IP 头、并基于 IP 做转发决策（路由）的交换机。**路由器**则是典型的纯三层设备。

## 第三部分：二层交换机的内部运作——三个操作

一台二层交换机，只做三件事：**学习**、**转发**、**泛洪**。理解这三个操作，就理解了交换机的全部。

### 核心：MAC 地址表（也叫 CAM 表）

交换机内部有一张表，记录"哪个 MAC 地址在哪个端口"。交换机刚开机时，这张表是**空的**。

```
┌────────────────────────────────┐
│  MAC 地址表（刚开机）            │
├──────────────┬─────────────────┤
│   MAC 地址    │   端口          │
├──────────────┼─────────────────┤
│   （空）      │   （空）         │
└──────────────┴─────────────────┘
```

### 操作一：学习（Learning）

交换机收到一个帧时，首先看这个帧的**源 MAC 地址**，然后把它和"从哪个端口收到的"记入 MAC 地址表。

```
PC-A（MAC: AA:AA:AA:AA:AA:01）接在端口 1，发送了一个帧。
交换机收到 → 记下：AA:AA:AA:AA:AA:01 → 端口 1
```

```
┌────────────────────────────────┐
│  MAC 地址表                     │
├──────────────────┬─────────────┤
│   MAC 地址        │   端口      │
├──────────────────┼─────────────┤
│ AA:AA:...:01     │   1         │
└──────────────────┴─────────────┘
```

注意一个关键点：**交换机学的是源 MAC，不会是目标 MAC**。

### 操作二：转发（Forwarding）

交换机学完源 MAC 后，看帧的**目标 MAC 地址**，查表：
- 如果表里有这个目标 MAC → **只从对应的那个端口发出去**（这就是"交换"的含义）
- 如果目标 MAC 和源 MAC 在同一个端口 → **直接丢弃**（不需要转发，目标已经收到了）

```
PC-A 发给 PC-B，PC-B 的 MAC 在端口 3：
  交换机只从端口 3 发出帧，端口 2、4、5……都不受影响。
```

### 操作三：泛洪（Flooding）

如果目标 MAC 不在表里呢？交换机不知道 PC-B 在哪个口，又不能不发——于是它把帧**从除了接收端口外的所有端口发出去**。

```
PC-A 第一次给 PC-B 发帧：
  MAC 表里没有 PC-B → 泛洪到端口 2、3、4、5……
  PC-B 收到，回复 → 交换机学到 PC-B 在端口 3
  从此，A→B 的帧就是精准转发了。
```

另外，**广播帧**（目标 MAC 是 `FF:FF:FF:FF:FF:FF`）和**组播帧**也会被泛洪。这就是为什么 ARP 广播会到达交换机的所有端口——交换机的 MAC 表只能帮助单播转发，无法拦截广播。

### 老化和更新

每个 MAC 表项都有**老化时间**（通常是 5 分钟）。如果 5 分钟内没有再收到来自这个 MAC 的帧，条目就会被删除。这防止了拔掉网线的设备的过期条目一直占用表空间。

### 一张表总结

| 帧类型 | 表中有目标 MAC？ | 交换机行为 |
|--------|-----------------|-----------|
| 单播 | 有 | 只往对应端口转发 |
| 单播 | 没有 | 泛洪到所有端口（除入口） |
| 广播（FF:FF:FF:FF:FF:FF） | — | 泛洪到所有端口（除入口） |
| 源 MAC 新出现 | — | 学习，记入 MAC 地址表 |
| 目标==源（同端口） | 有 | 丢弃（过滤） |

## 第四部分："二层"之上——三层交换机和路由器

### 二层交换机的局限

二层交换机只活在 MAC 地址的世界里，这让它有一个根本限制：**不能跨子网转发**。

你在交换机上接了 20 台设备，它们必须在同一个 IP 子网（比如都是 `192.168.1.0/24`），才能互相通信。如果要连到另一个子网（比如 `10.0.0.0/24` 里的服务器），**你必须经过路由器**。

这也是为什么你配网络的时候必须指定一个"默认网关"——那个网关就是路由器的地址，二层交换机不知道该怎么把包送到另一个子网，只能交给路由器。

### 三层交换机：把路由器"装进"交换机

**三层交换机** = 二层交换机 + 路由功能。它在硬件层面除了有 MAC 地址表，还有**路由表**，可以在不同子网/VLAN 之间转发数据。

当你用三层交换机做跨 VLAN 通信时，数据走的路径是：

```
PC-A（VLAN 10, 192.168.1.10）
  → 交换机 L2 转发到 VLAN 10 网关接口（交换机的虚拟 L3 接口）
  → 交换机查路由表，发现目标在 VLAN 20
  → 交换机 L2 转发到 VLAN 20 中的目标设备
  → PC-B（VLAN 20, 192.168.2.10）
```

整个过程只经过一台设备（三层交换机），而用纯二层交换机则需要：`交换机A → 路由器 → 交换机B`，多了一跳，延迟更高，而且路由器和交换机之间的链路经常是瓶颈。

### 三层交换机 vs 路由器：该买哪个？

| 对比维度 | 三层交换机 | 路由器 |
|----------|----------|--------|
| 转发方式 | 硬件（ASIC）转发，线速 | 多为 CPU 转发，性能受限 |
| 接口密度 | 高（24/48 口） | 低（通常 2-8 口） |
| WAN 接口 | 通常不支持 | 支持（PPPoE、NAT、防火墙） |
| NAT | 大多数不支持 | 支持 |
| 适用位置 | 局域网内部（核心层/汇聚层） | 局域网出口（连接外网） |

简单来说：**局域网内部跨子网用三层交换机；连外网用路由器。** 不要把三层交换机直接插光猫当出口——它通常做不了 NAT。

## 第五部分：网管 vs 非网管——你买到的到底是什么

回到开头那个"插上就能用"的铁盒子。

### 非网管交换机（Unmanaged Switch）

- 没有任何配置界面（没有 Web 后台、没有命令行）
- 即插即用，通电就能转发
- 所有端口在同一个广播域（没有 VLAN 能力）
- 不认识 802.1Q VLAN 标签——收到带标签的帧通常会直接丢弃
- 便宜（5 口千兆可能只要 50-80 块）
- 适用场景：家庭网络、小型办公室、所有设备在同一子网的环境

### 网管交换机（Managed Switch）

- 有 Web 管理界面和/或命令行（CLI，通常是类 Cisco 语法）
- 支持 VLAN 划分（802.1Q）
- 支持 SNMP 远程监控、端口镜像（抓包用）
- 支持链路聚合（多个端口绑成一条逻辑链路，提高带宽和冗余）
- 支持生成树协议（STP，避免二层环路）
- 支持 QoS（服务质量，优先转发 VoIP 或视频会议流量）
- 贵（8 口千兆网管交换机可能要 300-800 块）
- 适用场景：企业网络、需要 VLAN 隔离的环境

**一个让你死了心的实验：你买的非网管交换机能不能透传 VLAN？**

结论：**不能依赖它**。有些非网管交换机会因为不认识 802.1Q 头而直接丢弃带 Tag 的帧；有些"侥幸"能透传——但即使透传，终端设备也可以随意改 IP 切到任意 VLAN 的网段，没有任何安全保障。

如果你的上游交换机接了多个 VLAN，且你必须在末端接一台交换机，解决方案：
1. 买网管交换机，把对应端口划到需要的 VLAN
2. 或者让上游把该端口的 Native VLAN 设为你需要的 VLAN，你的非网管交换机就可以只用无标签帧工作

## 第六部分：VLAN、Access 口、Trunk 口——一个现实中的布线问题

假设你的办公室有 20 人，分别属于两个部门：研发部和市场部。从网络安全角度，两个部门的电脑不应该能直接互相访问。但你只有一台 24 口交换机。

你有两个选择：
- **A 方案**：买两台交换机，物理隔离——浪费端口，不灵活
- **B 方案**：用 VLAN（虚拟局域网），在一台交换机上逻辑隔离

### VLAN 做了什么

VLAN 本质上是在以太网帧的头部**插入了一个 4 字节的 802.1Q 标签**，里面包含一个 12 位的 VLAN ID（范围 1-4094）。交换机的内部逻辑是：**同一 VLAN 内部可以通信，不同 VLAN 之间默认不通**（除非通过三层路由）。

```
普通以太网帧：
┌──────────────┬─────────────┬──────────┬──────┐
│ 目标 MAC     │ 源 MAC       │ 类型      │ 载荷  │
└──────────────┴─────────────┴──────────┴──────┘

802.1Q VLAN 帧：
┌──────────────┬─────────────┬──────────────────┬──────────┬──────┐
│ 目标 MAC     │ 源 MAC       │ 802.1Q Tag (VLAN) │ 类型      │ 载荷  │
└──────────────┴─────────────┴──────────────────┴──────────┴──────┘
                                            ↑
                                     VLAN ID = 10
```

### Access 端口：接"平民"设备

连电脑、打印机、摄像头这些**不懂 VLAN 的终端设备**时，端口设为 Access 模式。

- 这个端口被固定划分到某一个 VLAN（比如 VLAN 10）
- 终端发出来的帧不带 VLAN 标签 → 交换机从 Access 口收到后，**打上 VLAN 10 的标签**再内部转发
- 交换机往这个端口发帧时，**移除 VLAN 标签**再发出去——终端完全不知道 VLAN 的存在

```
[PC] ──无标签帧──→ [Access Port, VLAN 10] ──Tagged VLAN 10──→ 交换机内部
```

### Trunk 端口：交换机之间的"高速公路"

两台交换机之间互联时，需要同时承载多个 VLAN 的流量。这时候端口设为 Trunk 模式。

- Trunk 口可以承载多个 VLAN（通过 VLAN 标签区分）
- 有一个 **Native VLAN**（典型是 VLAN 1），属于这个 VLAN 的帧不加标签发送
- 收到有标签的帧 → 按标签转发到对应的 VLAN
- 收到无标签的帧 → 归属到 Native VLAN

```
[交换机A Trunk] ──Tagged VLAN 10, 20, Native VLAN 1──→ [交换机B Trunk]
```

| 端口类型 | 接什么 | 传几个 VLAN | 是否打标签 |
|---------|--------|------------|-----------|
| Access | PC、打印机、摄像头 | 1 个 | 内部打标签，对外无标签 |
| Trunk | 交换机、路由器、服务器 | 多个 | 对外带标签（Native VLAN 除外） |

### 实验：手配一个简单的 VLAN

假设你有一台网管交换机（以下配置语法类 Cisco）：

```
! 创建 VLAN 10 和 20
vlan 10
 name R&D
vlan 20
 name Marketing
exit

! 把 1-12 口划到 VLAN 10（Access）
interface range gigabitEthernet 1/0/1-12
 switchport mode access
 switchport access vlan 10

! 把 13-24 口划到 VLAN 20（Access）
interface range gigabitEthernet 1/0/13-24
 switchport mode access
 switchport access vlan 20

! 把 25 口配为 Trunk，连上游交换机
interface gigabitEthernet 1/0/25
 switchport mode trunk
 switchport trunk allowed vlan 10,20
```

配完之后：
- 1-12 口的电脑互相能 ping 通
- 13-24 口的电脑互相能 ping 通
- 1-12 口的电脑 p 不通 13-24 口的电脑（不同 VLAN，二层隔离）
- 如果这台交换机是三层交换机，配了 L3 VLAN 接口为网关后，**VLAN 10 和 20 才能跨 VLAN 通信**

### 那台非网管交换机接 Trunk 口会怎样？

如果你把一台非网管交换机接到网管交换机的 Trunk 口：
- Trunk 口发的 **Native VLAN 的帧**（无标签）→ 非网管交换机正常转发
- Trunk 口发的**其他 VLAN 的帧**（有 802.1Q 标签）→ **大概率被丢弃**，因为非网管交换机不认识 0x8100 这个以太网类型字段

**结论：非网管交换机只能工作在单个 VLAN 模式下。你没法在上面做任何 VLAN 隔离。**

## 第七部分：动手实验

以下实验需要至少两台 Linux（虚拟机也可），通过虚拟网络或物理交换机连接。

### 实验一：观察 MAC 地址学习

```bash
# 在两台机器上查自己的 MAC 地址
ip link show eth0 | grep ether
# 输出：link/ether 08:00:27:ab:cd:ef

# 在机器 A 上查看 ARP 表（初始为空）
ip neigh show

# ping 机器 B
ping -c 1 192.168.1.20

# 再看 ARP 表——已经有 B 的条目了
ip neigh show
# 192.168.1.20 dev eth0 lladdr 08:00:27:12:34:56 REACHABLE
```

### 实验二：抓包看交换机泛洪 vs 转发

如果你的交换机有端口镜像功能（或使用 Linux bridge 模拟）：

```bash
# 在机器 A 上，先发一个 ARP 广播
arping -I eth0 192.168.1.20

# 在另一台不相关的机器 C 上抓包
sudo tcpdump -i eth0 -n arp
```

你能看到 ARP 广播（泛洪到所有端口）。但当 A 和 B 之间开始正常的 ICMP 单播通信后，机器 C 的抓包界面就没有新数据了——交换机的 MAC 表已经学习完毕，只做精准转发。

### 实验三：Linux bridge 模拟二层交换机

Linux 的 bridge 功能本质上就是一个软件二层交换机：

```bash
# 创建 bridge
sudo ip link add name br0 type bridge

# 加入两个虚拟接口
sudo ip link set veth1 master br0
sudo ip link set veth2 master br0

# 启动
sudo ip link set br0 up

# 查看 MAC 地址表（bridge 的 FDB）
bridge fdb show br br0
```

你会看到 bridge 自动学习到的 MAC 地址和对应的接口，跟物理交换机的 MAC 地址表一模一样。

### 实验四：验证不同 VLAN 不通（需网管交换机或 Linux VLAN）

```bash
# 在机器 A 上创建 VLAN 子接口
sudo ip link add link eth0 name eth0.10 type vlan id 10
sudo ip addr add 192.168.10.1/24 dev eth0.10
sudo ip link set eth0.10 up

# 在机器 B 上创建另一个 VLAN
sudo ip link add link eth0 name eth0.20 type vlan id 20
sudo ip addr add 192.168.20.1/24 dev eth0.20
sudo ip link set eth0.20 up

# 互相 ping
ping 192.168.20.1  # 不通！因为 VLAN 标签不同
```

## 第八部分：常见问答

### Q1："二层交换机"和"交换机"有什么区别？

没有区别。"交换机"默认指的就是二层交换机。只有明确说了"三层交换机"，才指带路由功能的交换机。日常说的"买个交换机"、淘宝上搜"交换机"，99% 都是二层交换机。

### Q2：我家里到底该买二层交换机还是三层交换机？

**二层，非网管。** 理由：家用路由器已经提供了 NAT、DHCP、基础路由，你只是需要更多网口。三层交换机在家用场景下完全是浪费，而且它做不了 NAT——你不能用它直接替换路由器。

### Q3：数据中心里是不是全用三层交换机？

数据中心的典型架构是 **Spine-Leaf**（脊叶架构）：Leaf 交换机（通常三层）接服务器，Spine 交换机（三层）做 Leaf 之间的互联。在这种架构下，二层只出现在 Leaf 到服务器的最后一段，其余都是三层路由。这样做的目的是消除二层环路、加快收敛、提高横向扩展能力。

### Q4：什么是 PoE 交换机？

PoE（Power over Ethernet，以太网供电）交换机可以通过网线同时传输数据和电力。你在办公室天花板上的 WiFi AP、走廊里的监控摄像头，很多都是用 PoE 交换机供电的——一根网线搞定一切，不需要再接电源适配器。

常见的 PoE 版本：
- **802.3af (PoE)**：最大 15.4W（够 IP 电话、基础 AP）
- **802.3at (PoE+)**：最大 30W（够大多数摄像头、高级 AP）
- **802.3bt (PoE++)**：最大 60W 或 100W（够笔记本、大屏显示器、PTZ 云台摄像头）

注意：PoE 交换机会在端口上输出 48V 直流电。不要把非 PoE 设备直接插到强制供电的 PoE 口上——可能会烧端口。

### Q5：交换机的"背板带宽"和"包转发率"怎么理解？

- **背板带宽（Switching Capacity）**：交换机内部所有端口之间能同时处理的最高吞吐量。千兆交换机 8 口全双工 → 背板带宽至少需要 8×2×1Gbps = 16 Gbps。
- **包转发率（Packet Forwarding Rate）**：交换机每秒能转发多少个包（pps）。千兆口的最小包（64 字节）线速转发需要 1.488 Mpps（百万包每秒）。

这两个参数是检验交换机是否"线速"（不丢包地跑满所有端口）的关键指标。便宜的交换机背板带宽可能不满足全端口全双工的要求——插满 8 口千兆设备并发打流，实际吞吐可能只有标称的一半。

## 写给不同角色

### 如果你是后端开发

你可能不需要配交换机，但你要知道：你的服务部署在多台机器上时，它们之间的网络延迟首先是交换机的转发延迟（通常 < 10 微秒）。如果机器在不同的 VLAN，中间经过路由器，延迟可能到 1-5 毫秒。这个差异在微服务调用链路中会被放大。另外，Docker Overlay 网络和 Kubernetes 的 CNI 都是在"用软件模拟交换机"——Flannel 的 VXLAN 模式本质上就是一个覆盖在物理网络上的虚拟二层。

### 如果你是运维/DevOps

你去机房配设备时，最常出问题的是：Access 口 vs Trunk 口配反了，或者 Trunk 口上漏了需要放行的 VLAN ID。上架新交换机前，确认三件事：管理 IP 配了没、VLAN 数据库建了没、端口模式设对了没。另外，别在生产网的 Trunk 口上把 Native VLAN 配成 VLAN 1 又允许它的标签帧——这就是经典的"VLAN 跳跃"安全漏洞。

### 如果你是前端

你不需要深入了解交换机。但如果你连不上后端 API、或者在办公室访问不到测试服务器，排查顺序是：先看 IP 能不能 ping 通（网络层），再看端口是否可达（传输层）。如果 ping 不通，问问运维你们的机器在不在同一 VLAN——跨 VLAN 又没有配置三层路由，就是不通的，跟前端代码没关系。

### 如果你是学生/转行者

找一台旧的网管交换机（闲鱼上 Cisco 2960 不到两百块），用 console 线连上去，把上面第六部分的命令敲一遍。配 VLAN、设 Access、配 Trunk、搭两台电脑互 ping。你亲手敲过一个 VLAN 配置，比读一百篇文章都管用。

## 小结

把这篇文章的内容压缩成几句话：

1. **交换机之所以叫"二层"，是因为它工作在 OSI 模型的第二层——数据链路层，只识别 MAC 地址，不认识 IP。**
2. **它的三个基本操作：学习源 MAC（建表）、转发已知目标 MAC（精准投递）、泛洪未知或广播目标 MAC（全端口发送）。**
3. **二层交换机不能跨子网——这是它有别于三层交换机和路由器的根本限制。**
4. **"非网管"意味着你不能配 VLAN、不能做任何定制，所有端口在一个广播域里。如果需要 VLAN 隔离，必须用网管交换机。**
5. **Access 口接终端（只属于一个 VLAN，无标签），Trunk 口接交换机（承载多个 VLAN，有标签）。**

交换机并不是神秘的东西。它本质上就是一台"有记忆的学习型信号分配器"——记住谁在哪，然后只给对的人送信。剩下的 VLAN、Trunk、三层路由，都是在这个基础之上的逻辑叠加。
