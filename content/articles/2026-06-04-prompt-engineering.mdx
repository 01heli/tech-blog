## 一、一个周末下午的挫败

你打开 ChatGPT，想让它帮你写一段 Python 代码——"帮我写一个读取 CSV 文件并计算平均值的脚本"。

它返回了 50 行代码，用了 pandas、matplotlib、还有一段你根本没要求的可视化逻辑。你皱皱眉，加了一句"用标准库，不要 pandas"。这次它给了 20 行，但硬编码了文件路径，而且没处理编码问题。

隔壁同事过来瞄了一眼你的屏幕，说："你把需求写得详细一点不就行了？"

于是你花了 15 分钟写了一篇 300 字的需求文档：输入格式、边界情况、编码处理、错误提示风格、输出格式、甚至给了一个示例。ChatGPT 终于给出了你想要的代码——一个干净、健壮、恰如其分的脚本。

刚才那 15 分钟写的 300 字"需求文档"，就是提示工程（Prompt Engineering）的雏形。

提示工程不是什么高深的术语。说白了，它就是**你怎么跟 AI 说话**——精确表达你的需求，让 AI 一次性返回你想要的结果。区别只是：跟人说话可以来回确认，跟 AI 说话是一次性输入，所以怎么写这个"输入"就成了一个值得研究的问题。

## 二、提示工程到底在"工程"什么

先看一个例子。假设你想让 AI 帮你把一段中文翻译成英文。

**普通提问：**
> "翻译：今天天气真好"

**提示工程做法：**
> "你是一名专业的中英翻译，翻译风格偏向商务正式。如果原文包含专业术语，请保留英文原文并在括号中注明中文释义。请只返回译文，不要加任何解释。
>
> 原文：今天天气真好
>
> 译文："

两种写法效果完全不同。第一种写法，AI 可能给你"Today's weather is really good"——语法没问题，但风格平淡。第二种写法设定了角色、风格、格式约束，返回的结果会是"It's a lovely day today"——更地道、更符合预期。

提示工程的"工程"，不在于写代码，而在于做三件事：

1. **框定范围**：告诉 AI 你是谁、它应该扮演什么角色、问题的领域边界在哪
2. **约束行为**：告诉它该做什么、不做什么、输出什么格式
3. **提供参照**：给一两个示例，让它知道你想要什么样的输出

这三件事同时做好的话，同一个模型在同一个任务上的表现可以差 3 到 5 倍。但三件事之间有微妙的平衡——有时候约束太多反而会让模型变得"死板"，这个后面再展开。

## 三、四种武器：从简单到复杂

提示工程发展到现在，最核心的技术可以归纳为四种。按照复杂度和适用场景排列：

### 3.1 零样本提示（Zero-Shot）

**最简单、最直接的方式**——不给任何示例，直接描述任务。

```
把下面这段话翻译成中文：
"The quick brown fox jumps over the lazy dog."
```

模型仅凭预训练阶段学到的知识来完成任务。对于翻译、摘要、简单分类这类"模型天然擅长"的任务，零样本就够了。不需要任何技巧。

但问题也很明显：当任务变复杂——比如要求特定格式、特定风格、或者需要多步推理——零样本提示就容易翻车。

### 3.2 少样本提示（Few-Shot）

**给模型看几个"范例"**。人类学习新事物的时候，往往看几个例子就懂了，模型也一样（这叫"上下文学习"，in-context learning）。

```
把下面的话翻译成英文，保持简洁口语风格。

例1：
中文：今天堵死了
英文：Traffic was insane today.

例2：
中文：这事儿太离谱了
英文：This is absolutely ridiculous.

现在翻译：
中文：我整个人都傻了
英文：
```

几个范例如同给模型定了一个"调性锚点"。研究表明，2~3 个高质量示例通常效果最好。超过 5 个示例可能出现"少样本崩溃"（Few-Shot Collapse）——示例太多反而干扰模型的判断，性能不升反降。

关于示例的排列顺序有一个小技巧：**把最重要的示例放在最后**。模型对最后看到的示例记忆最深刻，这个位置效应在多个实验中得到了验证。

### 3.3 思维链提示（Chain-of-Thought）

这是提示工程历史上最重要的单项突破——**2022 年 1 月，Google 的研究者发现，在 prompt 末尾加一句"让我们一步一步思考"（Let's think step by step），可以大幅提升模型在数学推理题上的准确率**。

原理其实很朴素：人类的思维是一步一步走的——"先算这个、再推那个、最后得出答案"。传统的问答模式下，模型直接从问题跳到答案，中间没有停顿思考的空间。思维链就是强制模型把推理过程写出来，相当于给它一个"草稿纸"。

```
问题：小明有 120 元，买书花了 35 元，又买文具花了剩下钱的 1/3，最后他还剩多少钱？

让我们一步一步思考：
1. 最开始有 120 元
2. 买书花 35 元 → 剩余 120 - 35 = 85 元
3. 买文具花剩余钱的 1/3 → 花 85 × 1/3 = 28.33 元 → 剩余 85 - 28.33 = 56.67 元
4. 最终剩余 56.67 元

答案：56.67 元
```

思维链有几种变体：

| 变体 | 做法 | 适用场景 |
|------|------|---------|
| **零样本思维链** | 直接加"让我们一步一步思考" | 通用推理，零成本提升 |
| **少样本思维链** | 自己写几个完整推理过程做示范 | 复杂推理、专业领域 |
| **自一致性（Self-Consistency）** | 让模型推理多次，取最常见的答案 | 高精度要求（金融、医疗、法律） |
| **思维树（Tree of Thoughts）** | 同时探索多条推理路径，剪掉明显错误的 | 策略类问题、复杂规划 |

自一致性的效果特别显著：某次实验中将数学推理准确率从 68% 提升到了 89%，代价只是多调用几次模型。

### 3.4 何时用哪种

```
任务简单直接 → 零样本（最快、最省 token）
任务需要特定格式/风格/领域 → 少样本（2~3 个高质量示例）
任务涉及多步推理/计算 → 思维链（加"逐步思考"）
高精度关键决策 → 少样本思维链 + 自一致性（多次推理取多数）
```

一个实用建议：**从零样本开始，不够再加少样本示例，还不行再引入思维链**。不要一上来就用最复杂的技巧，很多问题其实零样本就能很好地解决。

## 四、历史演进：为什么今天的提示工程和两年前完全不同

提示工程不是某个天才一夜之间发明出来的。它伴随着模型的能力演进，逐步从"经验分享"变成了一门"工程学科"。理解这段历史，你才能理解今天很多的做法为什么是这样、以及为什么有些做法已经过时了。

### 4.1 第一幕：模板时代（2018-2019）

```
BERT/GPT-1 时代
─────────────────────────
模型很小（1~3 亿参数）
完成任务靠"微调"（Fine-tuning）
```

2018 年 BERT 发布时，没人说"提示工程"。你想让模型做情感分类？你得准备几千条标注数据，用 BERT 做微调，得到一个新模型。即便到了 GPT-2，模型虽然有了一定的零样本能力，但整体上还是"训练一个新模型解决一个问题"的范式。

提示工程的影子，最早出现在 BERT 的**模板提示（Template Prompting）**——把分类任务包装成完形填空。比如让模型判断电影评论的情感：

```
"[CLS] 这部电影看得我热血沸腾，真是 [MASK] 极了"
```

模型在 `[MASK]` 位置填"棒"还是"烂"，就是它的情感判断。这算得上提示工程最初级的形态——用文本模板来引导模型的行为，但本质上还是在用微调模型的完形填空能力。

### 4.2 第二幕：提示工程诞生（2020-2022）

```
GPT-3 横空出世（1750 亿参数）
─────────────────────────
不需要微调！给几个示例就能完成任务
"提示工程"这个术语正式出现
```

2020 年 6 月 GPT-3 发布的那一刻，情况彻底变了。模型大到一定程度后，出现了一种"涌现能力"：**不需要微调，只要在 prompt 里给几个示例，模型就能完成新任务**。这在当时是一个惊人的发现——意味着你可以通过写文字来编程、分类、翻译、归纳，而不需要收集数据训练模型。

2022 年 1 月，**思维链（Chain-of-Thought）** 被提出，是提示工程的第一个重大突破。研究证明，在 prompt 中展示推理步骤能显著提升模型解决数学和逻辑问题的能力。同年 11 月，ChatGPT 发布，两个月内用户破亿，"提示词技巧"从学术圈走入大众视野。

这一阶段的核心主题是：**怎么把话写得更好，让模型更聪明**。Role Prompting（"你是一个专家"）、格式指定、Few-Shot、CoT——几乎所有今天我们熟知的提示技术，都在这个时期被提出。

### 4.3 第三幕：多模态与 Agent（2023-2024）

```
GPT-4 / Claude / Gemini
─────────────────────────
模型从"能说"进化到"能做"
提示工程不再只是文本游戏
```

GPT-4 能看图了，Claude 能记住一整本书了，Agent 能调用浏览器和终端了。提示工程的边界被急剧扩展——原来你控制的不仅仅是"说什么"，而是**一个能看、能听、能调用工具的自主系统的行为规范**。

2023 年的关键突破是 **ReAct**——"推理 + 行动"的提示模式。模型不再只是回答问题，它可以：

```
思考：我需要知道上海今天的天气
行动：调用天气查询工具
观察：上海的天气是 28°C 多云
思考：天气不错，适合户外活动
回答：今天上海 28°C，多云，很适合出门
```

提示工程从"写一段话"变成了"设计一个决策循环"。

### 4.4 第四幕：推理模型颠覆规则（2024-2025）

```
o1 / DeepSeek-R1 / Qwen3.5
─────────────────────────
模型自己会"想"了
之前行之有效的提示技巧开始失效
```

2024 年 9 月 OpenAI o1 发布，带出了一个新概念——**推理模型（Reasoning Model）**。简单说，这类模型在回答之前会先进行内部推理（相当于自动做思维链），你根本不需要在 prompt 里写"让我们一步步思考"。

这引发了提示工程领域的一次剧烈震荡。很多之前积累的"经验法则"突然变得不适用甚至有害：

| 旧技巧 | 对推理模型的影响 |
|--------|-----------------|
| "让我们一步一步思考" | 多余——模型已经在后台做了，加上只会增加延迟 |
| "你是一个专家级数据分析师" | 无实质性提升——角色扮演不能扩展模型的真实知识边界 |
| 大量 Few-Shot 示例（5+） | 反效果——"少样本崩溃"，示例过多反而降低性能 |
| 复杂的逐步指令 | 反效果——"提示反转"，简单明确的结果描述比冗长的过程指令效果更好 |

这就是 2025 年底开始被频繁提及的**提示反转（Prompting Inversion）**现象：对 GPT-5 等新模型而言，一句话说清"我要什么结果"，比十句话告诉它"你应该怎么做"效果好得多。

### 4.5 第五幕：从提示工程到上下文工程（2025-2026）

```
MCP / RAG / Agent 遍地开花
─────────────────────────
单条 prompt 优化已接近天花板
系统性设计模型的信息环境成为新焦点
```

2026 年的共识是：**幻觉几乎总是一个上下文问题，而不是提示词问题**。模型"编造"信息，往往不是因为你的 prompt 写得不够好，而是因为它没有看到正确的参考资料。

这一年，行业开始使用"上下文工程"来替代"提示工程"这个名称。区别在于：

| | 提示工程 | 上下文工程 |
|------|---------|-----------|
| 关注点 | 单条 prompt 的措辞 | 模型看到的完整信息环境 |
| 组成 | 指令 + 示例 + 格式 | 系统指令 + 检索资料 + 工具调用结果 + 对话历史 + 输出约束 |
| 典型操作 | 调整措辞、增减示例 | 设计 RAG 链路、管理对话记忆、编排工具调用、动态加载上下文 |
| 天花板 | 单轮优化空间有限 | 系统性提升空间大得多 |

一个数据点能说明这个转变的幅度：纯 prompt 优化的任务成功率为 **~8%**，加上动态上下文管理后提升到 **~42%**，再加上 Agent 的自主工具调用和纠错循环，可以达到 **~70%+**。

> **所以 2026 年的现实是：花 80% 精力在上下文设计上，20% 在 prompt 措辞上。反过来就是浪费时间。**

## 五、写提示词的框架：四个维度

理论说完了，我们来点实际的。不管技术怎么演进，面对当下的模型（2026 年你遇到的大概率是推理模型和常规模型混合），一个实用的 prompt 框架需要覆盖四个维度。

### 5.1 上下文（Context）

**把你的目标、背景、限制条件一次性塞给模型**，不要指望它自己去"理解"你的处境。

```
❌ "帮我分析下这个数据"

✅ "我是一家小型电商的运营人员，公司月 GMV 约 50 万。这是过去 6 个月的
   销售数据（CSV 附件）。请你帮我找出销量下降最明显的品类，并给出可能
   的原因分析。公司的主要客户群体是 25-35 岁的城市女性。"
```

第二个版本把"我是谁、干什么的、数据背景、客户画像"全交代了。模型有了这些信息，做出的分析会很不一样——它会结合客户画像去思考品类下降的原因，而不是给出一堆泛泛的"可能是季节性波动"。

### 5.2 输出格式

**如果你想要 JSON，就说你要 JSON。如果你想要 Markdown 表格，就说你要 Markdown 表格。**

```
❌ "帮我总结一下这篇文章"

✅ "请用以下 JSON 格式返回总结：
{
  "title": "文章标题",
  "one_sentence": "一句话总结",
  "three_points": ["要点1", "要点2", "要点3"],
  "keywords": ["关键词1", "关键词2", "关键词3"],
  "sentiment": "正面/中性/负面"
}"
```

指定格式不只是为了好看——明确的输出约束能够让模型减少"自由发挥"的空间，降低不确定性。研究显示，输出格式约束对文本质量的提升约为 40%，超过礼貌用语（"请"、"谢谢"）的效果。

### 5.3 "不要"清单

**告诉模型"不要做什么"常常比告诉它"要做什么"更有效。** 这被称为"负面约束"。

```
生成一份产品描述，要求：
- 不要使用"极致""非凡""卓越"等空洞的形容词
- 不要超过 200 字
- 不要提竞品的名称
- 不要使用过于技术化的术语（目标读者是普通消费者）
- 如果没有足够信息支撑某个观点，宁可跳过不要说
```

有团队实际测量过：加入"不要"清单后，编辑产出的时间减少了约 60%。为什么有效？因为人类写 prompt 的时候天然的盲点是"只定义想要什么，不定义不想要什么"，而模型在没有反面约束的情况下，会倾向于往"常见但不符合你具体场景"的方向生成。

### 5.4 示例的质量 > 数量

2~3 个精心挑选的示例远胜 10 个随便塞的示例。示例的质量标准：

- **覆盖边界情况**：如果任务有"常规情况"和"特殊处理"，示例要覆盖后者
- **展示失败处理**：如果输入可能是无效的，给一个"无效输入 → 友好提示"的示例
- **最后一个示例最关键**：模型对结尾附近的示例会给予更高权重

```
任务：从文本中提取日期并标准化格式

示例1（标准情况）：
输入："会议定在 2024年3月15日"
输出：{"date": "2024-03-15", "confidence": "high"}

示例2（模糊情况）：
输入："下周三之前提交"
输出：{"date": null, "confidence": "low", "note": "需要当前日期才能计算"}

现在提取：
输入："合同签署日期为 2025/06/01"
```

## 六、提示工程走向哪里：三个正在发生的变化

### 6.1 从"写操作手册"到"写验收标准"

传统思路是在 prompt 里写详细的步骤："先提取所有数字 → 然后计算总和 → 再除以总数 → 最后四舍五入到两位小数"。这在 2022 年的模型上是必要的。

现在的推理模型（o1 系列、DeepSeek R1、Qwen3.5 等），你只需要写验收标准：

```
计算这组数据的平均值，精确到两位小数。
```

模型自己会规划执行步骤——它本来就会推理了，你写一堆步骤反而限制了它的思考路径。有测量表明，迁移到"验收标准"模式后，有效 token 利用率从约 35% 提升到了 70%（35% 意味着传统 prompt 里 65% 的文字都在做无用功），维护成本降低了 60%~80%。

### 6.2 MCP 让提示工程变成了"资源配置"

Model Context Protocol（MCP）在 2026 年已成为行业标准，被纳入 Linux 基金会管理。它的核心价值是**让 prompt 不再需要携带所有信息——模型可以通过 MCP 动态获取所需的数据和工具**。

过去的 prompt：
```
你是数据分析师，我现在有数据如下：
[贴上一大段 CSV 数据]
请分析...
```

现在的 prompt：
```
你是数据分析师，使用 data_fetcher 工具读取 data/sales.csv，分析后输出报告。
```

MCP 的价值不只是节省 token。它让提示工程从"把信息塞进一句话"变成了"配置模型可以访问什么资源"——视角完全变了。

### 6.3 提示工程不会"死"，它只是基础设施化了

有一种论调说"提示工程要消亡了，因为模型越来越聪明"。这句话只对了一半。

低层次的"措辞调优"确实在贬值——当 GPT-5 能理解你说"大概整理一下"和"按优先级分类并标注紧急程度"之间的区别时，你不需要纠结怎么把话说得完美。

但更高层次的能力正在升值——**如何设计模型的信息环境（上下文工程）、如何编排多个模型的协作（Agent 编排）、如何建立评估体系验证 prompt 效果（Evals）**——这些才是一线 AI 工程师的核心工作。2026 年的招聘市场数据显示，掌握了上下文工程能力的工程师薪资溢价约在 35%。

## 七、总结：你的行动指南

| 你的角色 | 优先关注 |
|---------|---------|
| **普通用户** | 不必花太多时间学"提示词技巧"。把注意力放在**清晰描述你要什么结果**上，直接告诉 AI 你的目标、领域、约束和期望格式 |
| **开发者** | 从"怎么把 prompt 写好"转向"怎么把上下文搭好"——RAG 检索质量、工具接入（MCP）、输出验证、对话记忆管理，这些比措辞优化重要得多 |
| **AI 团队负责人** | 如果团队还没建立提示效果的量化评估体系，这是优先级最高的事。没有评估就没有优化方向 |
| **学习者** | 理解四种核心技巧（零样本 → 少样本 → 思维链 → 自一致性）之间的关系和适用场景，比背诵 100 个"万能 prompt 模板"有价值得多 |

三点核心建议：

1. **用简单清晰的语言，说清楚你要什么**。在 2026 年的模型面前，清晰胜过巧妙
2. **把 80% 的精力放在上下文设计上**。给模型正确的信息，比给它完美的指令更重要
3. **建立评估闭环**。不测量就无法改进。定期用真实案例检验你的 prompt 效果，而不是凭感觉调整
