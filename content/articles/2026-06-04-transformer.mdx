## 一、一个人读不完的长句子

假设给你一句话："小明把他昨天在二手书店淘到的那本泛黄的、封面已经磨损的《城堡》借给了小红，因为她说最近对卡夫卡产生了浓厚的兴趣。"

问题是：**"她"指的是谁？**

你大概花了不到一秒就得出答案——小红。你是怎么做到的？你读到"她"的时候，眼睛自然往前扫，找到了最近的那个女性人名。这个过程太自然了，自然到你不会意识到自己做了什么。

但如果让 2016 年的机器来做这件事呢？

当时的机器用的是 RNN（循环神经网络）。它的工作方式就像一个人只能用手指一个字一个字点着读，点完一个字才能看下一个字。每读完一个字，它必须把之前理解的内容压缩成一个固定长度的"记忆向量"，然后带着这个向量去看下一个字。

问题来了：读到"她"的时候，RNN 的"记忆"已经经过了四十多个字——"小明""把""他""昨天""在""二手书店""淘到""的""那本""泛黄的""封面已经磨损的""《城堡》""借给了""小红"……每一次压缩都丢失一点信息。到"她"这里，"小红"的痕迹早被冲淡了。这就是**长程依赖问题**——RNN 记不住太远的东西。

2017 年，Google 的八位研究者发表了一篇论文，标题只有六个英文单词：**"Attention Is All You Need"**（注意力就是你所需的全部）。这篇论文提出的 Transformer 架构，用了一个极其简单的想法颠覆了一切——

> 为什么非要一个字一个字地读？让每个字同时"看到"其他所有字不就行了？

这个想法改变了 AI 的历史走向。八年后的今天，你手机里的语音助手、ChatGPT、Midjourney 里的图像生成、AlphaFold 的蛋白质预测……背后全部站着 Transformer。

这篇文章会用大白话和可运行的代码，从零开始讲清楚 Transformer 到底是怎么工作的。不需要数学背景，不需要机器学习基础——你只需要好奇"那个能跟人对话的 AI 究竟是怎么理解语言的"。

## 二、注意力是一种本能

### 2.1 从人类阅读说起

回到开头那个句子。你在读"她"的时候，脑海里发生了什么？

你没有平等地对待每个前文——你的注意力是有选择性的。"小红"这个名字获得了最高权重，"小明"次之，"二手书店"、"泛黄的"这些几乎被忽略。你自动完成了一次**加权平均**：用 0.8 的"小红"加上 0.1 的"小明"加上 0.05 的"卡夫卡"……来理解"她"。

这就叫**注意力**。不是均匀地看所有东西，而是根据当前需要去挑选最相关的信息。

Transformer 的**自注意力**机制，就是把这个本能搬进了数学。

### 2.2 三个角色：Q、K、V

现在把句子里的每个词都想象成一个人，坐在一张圆桌的周围。每个"词人"身上带着三样东西：

| 角色 | 全称 | 问题 | 生活类比 |
|------|------|------|---------|
| **Q（Query，查询）** | 我想找什么？ | 你走进图书馆时的检索意图 | 你发出的关注"雷达" |
| **K（Key，钥匙）** | 别人怎么找到我？ | 每本书封面上的标签关键词 | 每个人身上的"身份标牌" |
| **V（Value，值）** | 我的具体内容是什么？ | 书的正文内容 | 真正要传递的信息 |

自注意力的计算过程只有三步：

```
第一步：用我的 Q 去和所有人的 K 做匹配，算出"我应该关注谁"
第二步：把这些匹配分数变成 0~1 之间的权重（softmax）
第三步：用权重去加权汇总所有人的 V，得到我的新表示
```

用生活场景类比：你参加一场会议，想就某个话题发表意见（Q = "我想知道和这个话题相关的内容"）。你扫一圈在场每一个人——有的人是专家（K 和你的 Q 高度匹配），有的人是跑题的（K 完全不沾边）。打分完后，你综合大家的发言内容（V），专家的意见权重高，跑题的几乎不采纳，最终形成你自己的发言稿。

关键洞察：**Q、K、V 都是从同一个输入变换出来的**。这就是"自"注意力的含义——句子里的词既是查询者又是被查询者，自己做题、自己打分。

### 2.3 把直觉变成数学

如果你对数学过敏，跳过这一段直接看 2.4 节，不影响理解大局。如果你想知道背后的计算，下面是精确的公式：

```
Attention(Q, K, V) = softmax(Q · Kᵀ / √d_k) · V
```

每一步的含义：

1. **Q · Kᵀ**（点积）：计算 Q 和每个 K 的相似度。两个向量越"方向一致"，内积越大。这一步得到的是一个"分数表"——"她"对"小红"打 95 分，对"苹果"打 12 分。

2. **÷ √d_k**（缩放）：d_k 是 Key 向量的维度（比如 64 维）。为什么要除以这个数？因为维度越高，点积结果越大，softmax 会被推到饱和区（梯度几乎为零），模型就学不动了。除以 √d_k 把方差控制住，这是一个工程上的关键细节。

3. **softmax**：把分数表变成"概率分布"——所有分数加起来恰好等于 1。这样就能解释为"注意力权重"了。

4. **× V**（加权求和）：注意力权重 × 每个人的内容 = 最终的"理解"。你能看出，"她"的新表示里包含了大量"小红"的信息、少量"小明"的信息，几乎不含"苹果"的信息。

> 为什么叫"Scaled Dot-Product Attention"（缩放点积注意力）？Scaled = 除以 √d_k 那个缩放操作；Dot-Product = Q·K 那个点积；Attention = 整个过程。

### 2.4 一段代码胜过千言万语

下面用 PyTorch 实现一次完整的自注意力计算。即使你不写代码，跟着注释读一遍也能理解整个过程：

```python
import torch
import torch.nn.functional as F

# 假设：句子有 6 个词，每个词用 512 维向量表示
batch_size = 1
seq_len = 6          # 句子长度：小明 把 苹果 给了 小红 她
d_model = 512        # 每个词的向量维度
d_k = 64             # Q/K 降维后的维度（比 512 小，降低计算量）

# 输入：6 个词 × 512 维
X = torch.randn(batch_size, seq_len, d_model)

# 三个权重矩阵：把原始词向量"投射"成 Q/K/V
W_Q = torch.randn(d_model, d_k)   # 512 → 64
W_K = torch.randn(d_model, d_k)   # 512 → 64
W_V = torch.randn(d_model, d_k)   # 512 → 64 (V 也降维到 64)

# 投射：每个词算出自己的 Q、K、V
Q = X @ W_Q   # (1, 6, 64)
K = X @ W_K   # (1, 6, 64)
V = X @ W_V   # (1, 6, 64)

# 计算注意力分数：Q 和 K 做内积
scores = Q @ K.transpose(-2, -1)         # (1, 6, 6) — 6×6 的"谁关注谁"矩阵
scores = scores / (d_k ** 0.5)           # 缩放，防止 softmax 饱和
attention_weights = F.softmax(scores, dim=-1)  # 每行变成一个概率分布

# 加权汇总 V：得到每个词的"新理解"
output = attention_weights @ V            # (1, 6, 64)

# 如果你打印 attention_weights[0][4]（第 5 个词"小红"的注意力分布）
# 你会看到它给第 0 个词（小明）和第 5 个词（她）分配了较高权重
# 这就是"小红"和"她"之间的关联被捕捉到了
```

核心要点：**在 Q·K 这一步里，每个词和所有词（包括自己）两两算了内积**。这就是并行化的秘密——不需要等前面的词处理完，所有词的计算可以同时进行。序列长度是 6，算出来就是一个 6×6 的注意力矩阵；序列长度是 1000，就是 1000×1000——这也是 Transformer 的主要计算瓶颈（后文会讲到 Flash Attention 如何解决它）。

## 三、多头注意力：一个人不只是一个人

只做一次自注意力够吗？不太够。

回到那个句子。"她"既需要关注"小红"（指代消解），又需要关注"卡夫卡"（语义关联），还需要关注"借给了"（语法结构）。**不同的关注角度要求不同的注意力模式**。单头注意力只能捕捉一种关系模式，多头注意力则并行捕捉多种模式。

### 3.1 为什么要多头

```
单头注意力：
  "她" → [0.8 × 小红 + 0.1 × 卡夫卡 + 0.05 × 借给了 + ...]
  问题：这三个权重来自同一个视角，"语法关系"和"指代关系"被搅在一起

多头注意力（以 8 头为例）：
  头 1："她" → [0.9 × 小红 + ...]     ← 这个头学了"指代消解"
  头 2："她" → [0.7 × 卡夫卡 + ...]   ← 这个头学了"主题关联"
  头 3："她" → [0.6 × 借给了 + ...]   ← 这个头学了"动词语法"
  头 4~8：各自捕捉其他模式（否定词、从句边界等）
  最终："她"的新表示 = Concat(头1输出, 头2输出, ..., 头8输出) × 投影矩阵
```

每个注意力头在计算之前，会先通过一个独立的投影矩阵把 Q/K/V 压到一个更小的子空间（比如 d_model=512, h=8, 则每个头的维度是 d_k=64）。在所有头里并行计算注意力，然后把 8 个结果拼接起来，经过最后一个线性变换回到原来的维度。

### 3.2 不同头学到了什么

研究者们分析过训练好的 Transformer 模型的注意力头，发现它们确实自动分化出了不同的分工：

| 头部类型 | 关注的模式 | 实际表现 |
|---------|-----------|---------|
| 句法头 | 主谓宾关系 | "她"重点关注"借给了"（谓语），"小明"关注"借"（主语动作） |
| 指代头 | 代词→实体 | "她"权重 0.8 分给"小红"，"它"权重 0.7 分给"《城堡》" |
| 语义头 | 词义相近的词 | "泛黄的"关注"磨损的"，"淘到"关注"二手书店" |
| 边界头 | 从句/短语边界 | 在"的"、"因为"处权重集中，帮模型理解句子结构 |
| 位置头 | 相邻词关系 | 类似 CNN 的滑动窗口，关注前后 1-2 个词 |

> 2025 年的一项研究还发现了一个有趣的现象：在混合架构（SSM + Attention）的模型中，只保留 **15% 的注意力头**就能维持接近完美的检索准确率，同时保住 84% 的 MMLU 基准分数。这意味着虽然每个头学的东西不一样，但存在大量冗余——不是所有头都同等重要。

### 3.3 完整的多头注意力代码

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        assert d_model % num_heads == 0, "d_model 必须能被 num_heads 整除"

        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads   # 每个头的维度 = 512/8 = 64

        # 四个线性变换：Q/K/V 的投影 + 输出的聚合投影
        # 注意：这里把 8 个头的 Q 投影合并成一个矩阵 (512 → 512)，然后再 reshape
        self.W_Q = nn.Linear(d_model, d_model)
        self.W_K = nn.Linear(d_model, d_model)
        self.W_V = nn.Linear(d_model, d_model)
        self.W_O = nn.Linear(d_model, d_model)

    def forward(self, X, mask=None):
        # X 的形状: (batch_size, seq_len, d_model)
        batch_size, seq_len, _ = X.shape

        # 1. 投影 Q/K/V 并拆分成多个头
        #    原始: (batch, seq_len, d_model)
        #    拆分: (batch, num_heads, seq_len, d_k)
        Q = self.W_Q(X).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        K = self.W_K(X).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        V = self.W_V(X).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)

        # 2. 计算缩放点积注意力
        scores = Q @ K.transpose(-2, -1) / (self.d_k ** 0.5)

        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))

        attention_weights = F.softmax(scores, dim=-1)
        attention_output = attention_weights @ V

        # 3. 拼接所有头的结果，投影回原维度
        #    (batch, num_heads, seq_len, d_k) → (batch, seq_len, d_model)
        concat = attention_output.transpose(1, 2).contiguous().view(
            batch_size, seq_len, self.d_model
        )
        return self.W_O(concat)
```

这段代码完整实现了原论文中的多头注意力层。实际使用中，PyTorch 已经内置了 `nn.MultiheadAttention`，但自己手写一遍才能真正理解"8 个头并行计算、然后拼接"到底在做什么。

## 四、架构全景：一个完整的 Transformer

### 4.1 总览

原论文的 Transformer 是一个**编码器-解码器**结构，专为机器翻译设计。编码器读入源语言句子（如英文），解码器逐词生成目标语言句子（如中文）。

```
输入："I love you"
        │
        ▼
┌───────────────┐
│   编码器      │
│  (Encoder)    │    6 层堆叠
│  ├ 自注意力    │   每层包含：
│  ├ 前馈网络    │    多头自注意力 → 残差+层归一化 → 前馈网络 → 残差+层归一化
│  └ ... ×6层   │
└───────┬───────┘
        │ 编码器输出（源语言的"理解"）
        ▼
┌───────────────┐
│   解码器      │
│  (Decoder)    │    6 层堆叠
│  ├ 掩码自注意力 │    每层包含：
│  ├ 交叉注意力  │    掩码多头自注意力 → 残差+LN → 交叉多头注意力(用编码器输出) → 残差+LN → 前馈网络
│  ├ 前馈网络    │
│  └ ... ×6层   │
└───────┬───────┘
        │
        ▼
输出："我爱你"
```

后来人们发现，把编码器和解码器拆开用，效果更好：

```
只用编码器 → BERT 系（理解任务：分类、检索、情感分析）
只用解码器 → GPT 系（生成任务：对话、续写、代码生成）
编码器+解码器 → T5 系（翻译、摘要等需要结构化转换的任务）
```

### 4.2 两个被低估的英雄：残差连接和层归一化

Transformer 的论文标题叫"Attention Is All You Need"，让很多人忽略了注意力之外的两个关键设计。没有它们，Transformer 根本训练不起来。

**残差连接**：把每一层的输入直接加到输出上。

```
正常的层：  输出 = 层(输入)
加残差后：  输出 = 层(输入) + 输入
```

为什么要这么干？2015 年 ResNet 的论文发现了深度神经网络的一个反直觉现象：56 层的网络在训练集上的错误率反而比 20 层的更高。不是过拟合——是梯度在反向传播经过 56 层之后衰减到了近乎为零，前面几层完全学不到东西。残差连接给梯度提供了一条"高速公路"——`+ 输入` 意味着梯度至少能原封不动传回去，保证即使 100 层的网络，前面几层也能收到有效的学习信号。

**层归一化**：把每一层的输出强行"掰"到均值为 0、标准差为 1 的分布。

```
输出 = (x - mean(x)) / std(x) * γ + β
```

神经网络各层的输出，数值范围越传越歪（内部协变量偏移），导致每层"看到的输入分布"都在变，训练很不稳定。层归一化把每层的输出强制拉回标准范围，让每一层都从稳定的起点开始学。这对训练速度的影响非常显著——不做归一化的 Transformer，收敛需要 3-4 倍的训练步数。

### 4.3 位置编码：给"不认顺序"的模型注入顺序感

自注意力有一个致命的盲区——它不知道词的位置。因为所有词同时参与计算，交换"小明"和"小红"的位置，注意力分数完全不变。但在中文里，"狗咬人"和"人咬狗"显然是两回事。

Transformer 的解决办法是**给每个位置分配一个独特的编码**，直接加到词向量上。词向量代表"这个词是什么意思"，位置编码代表"这个词在哪儿"，两者叠加后一起进入注意力层。

原论文用的是**正弦/余弦函数**生成位置编码：

```python
def sinusoidal_positional_encoding(seq_len, d_model):
    PE = torch.zeros(seq_len, d_model)
    position = torch.arange(seq_len).unsqueeze(1).float()       # (seq_len, 1)
    # 维度 0,2,4,... 用 sin；维度 1,3,5,... 用 cos
    div_term = torch.exp(
        torch.arange(0, d_model, 2).float() * (-torch.log(torch.tensor(10000.0)) / d_model)
    )
    PE[:, 0::2] = torch.sin(position * div_term)    # sin(pos / 10000^(2i/d))
    PE[:, 1::2] = torch.cos(position * div_term)    # cos(pos / 10000^(2i/d))
    return PE
```

为什么用正弦波而不是直接给位置编号（1, 2, 3, ...）？两个原因：

1. **任意两个位置之间的关系是固定的**。pos=5 和 pos=8 之间的编码差值，与 pos=0 和 pos=3 之间的编码差值完全相同——都是距离 3。模型可以从编码差值中读到"相对位置"。

2. **可以外推到训练时没见过的长度**。训练时句长 100，推理时句长 200——正弦函数照样能生成第 101~200 个位置的编码，而如果用学习式的编码（给每个位置单独学一个向量），第 101 个位置根本没学过。

不过 2025 年的主流模型大多改用了 **RoPE（旋转位置编码）**——不是把位置编码加在词向量上，而是用旋转矩阵在注意力计算阶段直接旋 Q 和 K 向量。被 LLaMA 系列采用后，RoPE 几乎成了现代 LLM 的标配，配合 YaRN 等技术甚至能把上下文窗口扩展到 128K token。

### 4.4 编码器块的完整代码

把多头注意力、残差连接、层归一化、前馈网络拼成一层编码器：

```python
class EncoderLayer(nn.Module):
    def __init__(self, d_model=512, num_heads=8, d_ff=2048, dropout=0.1):
        super().__init__()
        self.self_attention = MultiHeadAttention(d_model, num_heads)
        self.feed_forward = nn.Sequential(
            nn.Linear(d_model, d_ff),   # 512 → 2048 升维
            nn.ReLU(),
            nn.Linear(d_ff, d_model),   # 2048 → 512 降回
        )
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, X):
        # 子层 1：多头自注意力 + 残差 + LN
        attn_out = self.self_attention(X)
        X = self.norm1(X + self.dropout(attn_out))    # 残差 + 归一化

        # 子层 2：前馈网络 + 残差 + LN
        ff_out = self.feed_forward(X)
        X = self.norm2(X + self.dropout(ff_out))       # 残差 + 归一化

        return X
```

前馈网络里那个 `2048` 很有意思：先把维度从 512 拉高到 2048（升维→非线性→降维），这是一个经典的"漏斗"设计。直观理解：注意力层负责"谁跟谁有关系"（横向交互），前馈网络负责"这个信息意味着什么"（纵向深化）。先升维再降维给了模型更大的容量去处理每个位置的独立信息。

## 五、为什么 Transformer 能赢：跟 RNN 算一笔账

| 维度 | RNN/LSTM | Transformer |
|------|----------|-------------|
| 处理方式 | 逐词串行：处理完第 1 个词才能处理第 2 个 | 所有词同时处理 |
| 长程依赖 | 信息经过 N 步传递，距离超过 20 步衰减严重 | 任意两词直接交互，路径长度 O(1) |
| 训练速度 | 无法有效利用 GPU 并行（必须等上一步结果） | 高度并行，速度为 RNN 的 5~100 倍 |
| 序列长度上限 | 受梯度消失限制，实际只能处理 50-100 步依赖 | 理论上无上限，实际受显存限制（O(n²)） |
| 可解释性 | 难以解释"为什么这样输出" | 可可视化注意力权重，看到"这个词注意到那个词" |

训练一个英文→德文翻译模型：RNN 需要几周，Transformer 在 8 块 P100 GPU 上只需 3.5 天（big 模型），翻译质量（BLEU 分数）还高了 2.0 分。对这个领域的人来说，这就像是某天突然有人告诉你"盖一栋楼的时间从两年变成了三周，而且质量更好"。

## 六、一个家族的三条血脉

### 6.1 GPT：只顾左边

GPT 只用了解码器，而且是"掩码版"的解码器——每个词只能看到自己和它左边的词，不能偷看右边。这是为了适应用"预测下一个词"的方式训练：

```
输入：  "今天 天气 很"
目标：  "天气 很 好"
         ↑   ↑   ↑
       第1步 第2步 第3步（每一步都只看到左边的词，预测右边那个）
```

这种"单向"的约束看起来很笨——明明右边有线索为什么不看？但正是这个约束让 GPT 获得了强大的**零样本泛化能力**。"预测下一个词"不需要任何人工标注数据——互联网上的任意网页、任意书籍都可以变成训练样本（把每个句子当成"已知前文、预测下一个词"的任务）。数据量从"我们标注了多少"变成了"人类写了多少"，这是 GPT-3 能在 2020 年震惊世界的最根本原因。

到 GPT-4 时代，模型已经能处理图像输入、调用外部工具、写几百行代码。但它的核心骨架，依然是 2017 年那篇 6 页论文里的解码器。

### 6.2 BERT：两边都看

BERT 用编码器，同时看上下两个方向。训练方式不是"预测下一个词"，而是**完形填空**——随机遮住句子里的 15% 的词，然后让模型根据上下文猜出被遮住的词。

```
输入：  "我 [MASK] 吃苹果"     → 预测："爱"（75%）、"想"（12%）、"要"（8%）
输入：  "小明把苹果 [MASK] 了小红" → 预测："给"（94%）
```

第二个例子很说明问题——要填对这个空，模型必须理解"小明→苹果→小红"的三元关系和"给"这个双宾动词的语法要求。仅仅是被动地"看完形填空"就能学到这些，证明大规模无监督预训练本身就蕴含着强大的语义学习力。

BERT 系在文本分类、命名实体识别、问答系统等"理解型"任务上长期霸榜，直到现在依然是企业级 NLP 系统（合规审查、客服路由、文档检索）的主力。它的劣势也很明显——不能生成连续文本，你没法让它"写一篇文章"。

### 6.3 ViT：把图片当成句子处理

2020 年，Google 的研究者问了一个问题：如果把图片切成一个个小块（patch），当成"视觉单词"送进 Transformer，会怎样？

```
一张 224×224 像素的图片：
┌──┬──┬──┬──┐
│1 │2 │3 │4 │   16×16 的网格 = 196 个 patch
├──┼──┼──┼──┤   每个 patch 14×14 像素
│5 │6 │7 │8 │   → 拉平 → 经过线性投影 → 得到 196 个"视觉词向量"
├──┼──┼──┼──┤   → 加位置编码 → 送进 Transformer 编码器
│..│..│..│..│
└──┴──┴──┴──┘
```

结果就是 Vision Transformer (ViT)：**纯 Transformer 架构，没有任何卷积操作**，在 ImageNet 上达到了 85.3% 的准确率，超越了当时的 ResNet。此前所有人认为卷积（CNN）是处理图像的不可替代的基础操作——局部感受野、参数共享、平移不变性。ViT 证明了只要数据量够大，Transformer 的自注意力完全可以自己学会"哪里是边缘""哪里是纹理""哪些 patch 应该放在一起看"。

此后衍生出的 Swin Transformer（引入局部窗口注意力）、DETR（端到端目标检测）、SAM（Meta 的通用图像分割模型）等，让 Transformer 在计算机视觉领域也成了默认骨架。

### 6.4 三条血脉的选型指南

```
                    你的任务是什么？
                         │
          ┌──────────────┼──────────────┐
          │              │              │
       需要生成       需要理解       需要转换
      （写文章、       （分类、       （翻译、
       写代码、       情感分析、      摘要、
       对话）         实体识别）      SQL生成）
          │              │              │
          ▼              ▼              ▼
       GPT 系         BERT 系         T5 系
    (decoder-only)  (encoder-only)  (encoder-decoder)

      ChatGPT         情感分析        mT5
      GitHub          客服路由         BART
      Copilot         合同审查        Whisper
```

一个简单的心智模型：**encoder 负责"读懂"，decoder 负责"写出来"**。只需要读懂 → BERT；只需要写出来 → GPT；需要先读懂再写出来 → T5。

## 七、动手：从头搭一个微型 Transformer

下面这段代码构建了一个能训练的微型 Transformer（约 1M 参数，适合 CPU 跑），完整包含了上面讲的所有组件。用在一个"把源码序列反转"的玩具任务上做验证。

```python
import torch
import torch.nn as nn
import math

class MiniTransformer(nn.Module):
    """一个微型编码器-解码器 Transformer，适合学习用"""

    def __init__(self, vocab_size=1000, d_model=128, num_heads=4,
                 num_layers=2, d_ff=512, max_len=100, dropout=0.1):
        super().__init__()
        # 词嵌入 + 位置编码
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.position_embedding = nn.Embedding(max_len, d_model)

        # 编码器：num_layers 层
        self.encoder_layers = nn.ModuleList([
            EncoderLayer(d_model, num_heads, d_ff, dropout)
            for _ in range(num_layers)
        ])

        # 解码器：num_layers 层
        self.decoder_layers = nn.ModuleList([
            DecoderLayer(d_model, num_heads, d_ff, dropout)
            for _ in range(num_layers)
        ])

        self.output_projection = nn.Linear(d_model, vocab_size)
        self.dropout = nn.Dropout(dropout)

    def encode(self, src_tokens):
        """编码源序列"""
        batch_size, seq_len = src_tokens.shape
        positions = torch.arange(seq_len, device=src_tokens.device).unsqueeze(0)

        # 词嵌入 + 位置嵌入
        X = self.token_embedding(src_tokens) + self.position_embedding(positions)
        X = self.dropout(X)

        # 过编码器各层
        for layer in self.encoder_layers:
            X = layer(X)
        return X   # (batch, src_len, d_model) — 源语言的"理解"

    def decode(self, tgt_tokens, encoder_output, tgt_mask=None):
        """逐位置生成目标序列"""
        batch_size, seq_len = tgt_tokens.shape
        positions = torch.arange(seq_len, device=tgt_tokens.device).unsqueeze(0)

        X = self.token_embedding(tgt_tokens) + self.position_embedding(positions)
        X = self.dropout(X)

        for layer in self.decoder_layers:
            X = layer(X, encoder_output, tgt_mask)
        return X   # (batch, tgt_len, d_model)

    def forward(self, src_tokens, tgt_tokens):
        encoder_output = self.encode(src_tokens)

        # 构建因果掩码：第 i 个位置只能看到 0~i，看不到 i+1 及之后
        tgt_len = tgt_tokens.shape[1]
        tgt_mask = torch.tril(torch.ones(tgt_len, tgt_len)).to(src_tokens.device)

        decoder_output = self.decode(tgt_tokens, encoder_output, tgt_mask)
        logits = self.output_projection(decoder_output)   # (batch, tgt_len, vocab_size)
        return logits


# ---- 训练玩具任务：反转数字序列 ----
# 输入 [1, 5, 8, 3, 9] → 期望输出 [9, 3, 8, 5, 1]
# 这是一个简单但需要"看到整个序列"的任务，RNN 处理不好，Transformer 轻松做到

def train_toy_task():
    model = MiniTransformer(
        vocab_size=20, d_model=64, num_heads=2,
        num_layers=2, d_ff=256, max_len=20
    )
    optimizer = torch.optim.Adam(model.parameters(), lr=0.001)
    loss_fn = nn.CrossEntropyLoss()

    for step in range(1000):
        # 随机生成 5-8 个数字的序列
        length = torch.randint(5, 9, (1,)).item()
        src = torch.randint(1, 15, (1, length))       # 源序列
        tgt_input = torch.cat([torch.tensor([[0]]), src.flip(1)[:, :-1]], dim=1)  # 解码器输入(shifted)
        tgt_target = src.flip(1)                       # 目标 = 反转序列

        logits = model(src, tgt_input)
        loss = loss_fn(logits.squeeze(0), tgt_target.squeeze(0))

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()

        if step % 200 == 0:
            print(f"Step {step:4d}, Loss: {loss.item():.4f}")

    # 验证
    with torch.no_grad():
        test_src = torch.tensor([[3, 7, 1, 9, 5]])
        encoder_out = model.encode(test_src)
        generated = [0]  # 起始符
        for _ in range(10):
            tgt = torch.tensor([generated])
            dec_out = model.decode(tgt, encoder_out)
            next_token = model.output_projection(dec_out)[0, -1].argmax().item()
            generated.append(next_token)
            if next_token == 2:   # 结束符
                break
        print(f"输入: {test_src.tolist()}")
        print(f"输出: {generated}")  # 应接近 [3, 7, 1, 9, 5] 的反转

if __name__ == "__main__":
    train_toy_task()
```

运行这段代码，你会看到损失从 ~2.5 逐渐下降到 ~0.01，最后输出确实是输入的反转。这是一个特意设计的简单任务，但它验证了一个重要的事情：**自注意力确实能捕捉到任意距离的依赖关系**——序列末尾的词需要和序列开头的词交换位置，它们之间的距离是最长的，但模型做到了。

## 八、Transformer 的代价与解决方案

### 8.1 O(n²)——那个绕不开的瓶颈

自注意力的复杂度是 **O(n²)**，n 是序列长度。n=1000 时要算 100 万对内积，n=100000 时要算 100 亿对内积——显存直接爆炸。这也是 GPT-4 的上下文窗口从 8K→32K→128K 每次扩展都如此艰难的根本原因。

2022 年提出的 **Flash Attention** 是一个算法层的解决方案。思路很简单：自注意力中最耗时的不是计算本身，而是反复读写高带宽内存（HBM）。Flash Attention 把大矩阵切分成小块，每次只加载一小块到 SRAM（快但容量小），算完立刻丢弃中间结果，需要的时候再重新算。结果：

| 指标 | 标准注意力 | Flash Attention 2 |
|------|-----------|-------------------|
| 内存复杂度 | O(n²) | O(n) |
| 计算速度 | 1× | 2-4× 更快 |
| 可处理的最大序列长度 | ~8K | >128K |
| 数学等价性 | — | 完全等价（不是近似！） |

Flash Attention 已经集成到 PyTorch 2.0+ 中（`torch.nn.functional.scaled_dot_product_attention`），用户不需要改任何代码就能自动受益。

### 8.2 位置编码的进化

原论文用的是正弦位置编码，但现在的主流方案已经演变了好几轮：

| 方案 | 原理 | 代表模型 | 优缺点 |
|------|------|---------|--------|
| 正弦编码 | sin/cos 函数 | 原版 Transformer | 可外推，但表达能力弱 |
| 学习式编码 | 每个位置学一个向量 | BERT, GPT-1 | 表达强，但无法外推 |
| RoPE | 用旋转矩阵旋 Q/K | LLaMA, Qwen, GPT-NeoX | 相对位置天然编码，可配合 YaRN 扩展到 128K |
| ALiBi | 注意力分数减去距离惩罚项 | BLOOM | 强外推能力、零额外开销，但不兼容 Flash Attention 2 某些实现 |

**RoPE 为什么受欢迎？** 它把"位置差异"直接编码进了 Q 和 K 的内积中。两个 token 之间的内积不再只反映语义相似度，而是天然包含了它们的相对位置。这意味着模型不需要额外"学"位置关系——旋转角度天然就是距离的函数。

### 8.3 不只是文本：多模态统一

2024-2025 年最显著的趋势是多模态统一。GPT-4o 可以同时听你的语音、看你的摄像头画面、读你屏幕上的文字、理解你上传的 PDF——所有这些输入在同一个 Transformer 里处理。

实现方式不是把不同模态的模型"粘在一起"，而是把一切都变成 token：

```
文本 token：   [词1] [词2] [词3] ...
图像 token：   [图块1] [图块2] ... [图块196]
音频 token：   [梅尔频谱段1] [段2] ...
代码 token：   [def] [函数名] [(] [参数] [)]

全部扔进一个 Transformer，用"预测下一个 token"统一训练
```

这就解释了为什么 GPT-4o 能够在你看摄像头时实时描述"你手里拿的是个蓝色的杯子"——它不是分别用"视觉模型"和"语言模型"处理完再拼接，而是**在同一个注意力矩阵里**，"杯子"这个词直接关注了图像 patch 中蓝色圆形区域。

## 九、给你自己的行动指南

### 如果你是初学者

1. **先理解直觉，再看数学**。本文的 Q/K/V 类比和多头注意力的分工表比先背公式重要得多。理解了"每个词看一眼所有其他词"，再去想矩阵乘法怎么实现。
2. **跑一遍第七节的代码**。把 `MiniTransformer` 复制到 Jupyter Notebook 里，修改参数（num_layers=1 vs 4, d_model=64 vs 256），观察 loss 曲线的变化。动手调参比看十篇博客都管用。
3. **用可视化工具看注意力权重**。`bertviz` 或 `exBERT` 可以让你点进一个层、一个头，看到它"在关注谁"。亲眼看到"她→小红"的注意力连接，比任何文字解释都直观。

### 如果你是后端/应用开发者

1. **不需要从头训模型**。Hugging Face 上有超过 50 万个预训练模型，你只需要学会 `model = AutoModel.from_pretrained("...")` 和 `pipeline()` 两个 API。
2. **选对架构类型**。分类/检索/NER → BERT 系 (`bert-base-chinese`)；生成/对话 → GPT 系，通过 API 调云端模型；翻译/摘要 → T5/mBART。
3. **显存是硬通货**。部署时一个 7B 参数的模型在 FP16 精度下需要约 14GB 显存。用 INT4 量化（`bitsandbytes`）可以压到 ~4GB，在消费级显卡上也能跑。

### 如果你是算法工程师

1. **Flash Attention 是免费午餐**。升级 PyTorch ≥ 2.0，训练和推理速度提升 2-4 倍，不需要改任何模型代码。
2. **RoPE + YaRN 是长上下文的标配**。如果需要在预训练聊天模型上扩展上下文窗口，YaRN 在 0.1% 的微调数据量和 1/2.5 的训练步数下即可把 4K 窗口模型推到 128K。
3. **注意力头的冗余比你想象的大**。2025 年的研究表明 85% 的头是可以剪掉的。如果你在做推理优化，剪枝注意力头比量化参数的收益更直接——既能减显存又几乎不掉精度。

### 如果你是架构师/技术负责人

1. **优先考虑 API 而非自建**。除非你有独特的领域数据和明确的精度要求，否则基于 GPT-4o/Claude 的 API 方案比自训模型成本低一个数量级。
2. **RAG + Transformer 是企业级标配**。不要试图微调一个"知道所有公司文档"的模型。用 BERT 系做文档检索，用 GPT 系做答案生成，两者分离、各自迭代（如果你对这个话题感兴趣，可以参考我的 [RAG 深度解析文章](/articles/2026-05-30-rag-deep-dive)）。
3. **关注成本结构**。一个 1000 万日活用户的对话产品：云端 API 方案每月 ~$50K；自建 7B 模型推理集群每月 ~$20K（硬件 + 运维）。后者前期投入大，但边际成本低——随着用户增长，交叉点迟早到来。

## 十、一个简单的总结

2017 年的那篇论文只有六页。六页，改变了整个 AI 行业。

它改变的不只是技术架构，更是一种思维方式。在 Transformer 之前，"处理序列 = 按顺序处理"似乎是天经地义的。RNN 家族统治了序列建模二十年，人们的所有改进都在"如何让这个顺序处理更高效、记得更久"的框架里打转。Transformer 说：**不需要顺序**。你只需要让每个元素看一眼其他所有元素，然后自己决定该关注谁。

这个想法的力量，到今天还在持续发酵。从文本到图像，从代码到蛋白质，从单模态到多模态，"注意力的架构"正在成为一切智能系统的基础语言。

- [FlashAttention: Fast and Memory-Efficient Exact Attention (Dao et al., 2022)](https://arxiv.org/abs/2205.14135)（将注意力机制内存复杂度从 O(n²) 降到 O(n) 的算法，已在 PyTorch 2.0+ 中默认集成）
- [RoFormer: Enhanced Transformer with Rotary Position Embedding (Su et al., 2021)](https://arxiv.org/abs/2104.09864)（RoPE 旋转位置编码的原论文，LLaMA/Qwen/GPT-NeoX 等主流模型的位置编码方案来源）
- [YaRN: Efficient Context Window Extension (Peng et al., 2023)](https://arxiv.org/abs/2309.00071)（将 LLaMA 上下文窗口从 4K 扩展到 128K 的高效微调方法，仅需 0.1% 的微调数据量）
- [An Image is Worth 16x16 Words: Transformers for Image Recognition at Scale (Dosovitskiy et al., 2020)](https://arxiv.org/abs/2010.11929)（Vision Transformer 原论文，证明了纯 Transformer 架构在计算机视觉领域的可行性）
- [Some Attention is All You Need for Retrieval (arXiv, 2025)](https://arxiv.org/html/2510.19861)（2025 年关于 SSM+Attention 混合架构中注意力头角色的最新研究，发现仅 15% 的注意力头即能维持检索准确率）
- [Transformer 自注意力机制：我用通俗语言和代码给你整明白 (腾讯云)](https://cloud.tencent.cn/developer/article/2539651)（面向零基础读者的中文自注意力教程，PyTorch 代码 + 生活类比）
- [Transformer 架构的数学本质 (华为云)](https://bbs.huaweicloud.com/blogs/458411)（从数学推导角度深入拆解 Transformer 各组件，适合想理解背后原理的读者）
- [大模型分类体系与应用场景全景解析 (百度开发者)](https://developer.baidu.com/article/detail.html?id=3659147)（2025 年大模型生态全景图，覆盖 GPT/BERT/ViT/多模态各分支的最新进展）
- [从 Transformer 到 DeepSeek-R1：AI 大模型的八年技术跃迁 (百度开发者)](https://developer.baidu.com/article/detail.html?id=3807170)（2017-2025 年大模型技术演进的时间线梳理，适合建立历史视角）
