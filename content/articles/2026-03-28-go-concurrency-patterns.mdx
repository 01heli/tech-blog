## Go 的并发哲学

"Do not communicate by sharing memory; instead, share memory by communicating."

Rob Pike 的这句话定义了 Go 的并发编程范式。Goroutine 和 Channel 是实现这一范式的两大基石。

## GMP 调度模型

Go 运行时使用 GMP 模型来管理 goroutine 的调度：

- **G (Goroutine)**：用户态的轻量级线程，初始栈大小仅 2KB
- **M (Machine)**：操作系统线程，G 需要运行在 M 上
- **P (Processor)**：调度上下文，包含可运行的 G 队列，数量由 `GOMAXPROCS` 决定

```
┌──────────────────────────────────┐
│          Go Runtime              │
│  ┌────┐ ┌────┐ ┌────┐           │
│  │ G  │ │ G  │ │ G  │  (Local Q)│
│  └────┘ └────┘ └────┘           │
│       ↓     ↓     ↓             │
│  ┌─────────────────┐            │
│  │        P        │            │
│  └────────┬────────┘            │
│           │                     │
│  ┌────────┴────────┐            │
│  │        M        │            │
│  └─────────────────┘            │
└──────────────────────────────────┘
```

## Channel 使用模式

### Fan-Out / Fan-In

```go
func fanOut() {
    jobs := make(chan int, 100)
    results := make(chan int, 100)

    // Fan-out: 启动多个 worker
    for w := 0; w < 10; w++ {
        go worker(jobs, results)
    }

    // 分发任务
    for i := 0; i < 100; i++ {
        jobs <- i
    }
    close(jobs)

    // Fan-in: 收集结果
    for i := 0; i < 100; i++ {
        <-results
    }
}
```

### Or-Done Pattern

当需要同时监听多个 channel 的消息时：

```go
func orDone(done <-chan struct{}, c <-chan interface{}) <-chan interface{} {
    valStream := make(chan interface{})
    go func() {
        defer close(valStream)
        for {
            select {
            case <-done:
                return
            case v, ok := <-c:
                if !ok {
                    return
                }
                select {
                case valStream <- v:
                case <-done:
                }
            }
        }
    }()
    return valStream
}
```

### Pipeline Pattern

通过 channel 连接多个处理阶段，每个阶段可以独立扩展：

```go
func pipeline() {
    // Stage 1: 生成数字
    gen := func(nums ...int) <-chan int {
        out := make(chan int)
        go func() {
            for _, n := range nums {
                out <- n
            }
            close(out)
        }()
        return out
    }

    // Stage 2: 平方
    sq := func(in <-chan int) <-chan int {
        out := make(chan int)
        go func() {
            for n := range in {
                out <- n * n
            }
            close(out)
        }()
        return out
    }

    // 组合 pipeline
    for n := range sq(sq(gen(2, 3))) {
        fmt.Println(n) // 16, 81
    }
}
```

## Context 传递与取消

```go
func callService(ctx context.Context) error {
    ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
    defer cancel()

    req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return fmt.Errorf("request failed: %w", err)
    }
    defer resp.Body.Close()
    // ...
}
```

### 关键原则

1. **Context 是请求范围的，不要存储在结构体中**
2. **总是 defer cancel()**
3. **不要传递 nil context，用 `context.TODO()` 代替**

## 常见的并发陷阱

> ⚠️ **Goroutine 泄漏**：永远确保 goroutine 可以退出。使用 `context` 或 `done` channel 传递取消信号。

> ⚠️ **资源竞争**：用 `go run -race` 检测数据竞争。这是 Go 编译器自带的竞态检测器，遇到竞争时会在 stderr 输出详细报告。

记住：并发不是并行。并发是结构，并行是执行。
