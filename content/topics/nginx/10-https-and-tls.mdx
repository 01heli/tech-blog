## 为什么 HTTPS 不再是可选项

几年前，HTTPS 还是"电商网站才需要"的东西。今天，情况完全不同：

1. **Chrome 标记 HTTP 网站为"不安全"** —— 用户看到锁旁边有个红色警告
2. **HTTP/2 只支持 HTTPS** —— 想要更快的网页加载速度？上 HTTPS
3. **SEO** —— Google 明确表示 HTTPS 是排名因素
4. **Let's Encrypt 免费** —— 再也没有"证书太贵"的借口

## 快速获得免费证书（Let's Encrypt + Certbot）

Let's Encrypt 提供完全免费的 DV（域名验证）证书，有效期 90 天，可以自动续期。

### 安装 Certbot

```bash
# Ubuntu/Debian
sudo apt install certbot python3-certbot-nginx

# CentOS/RHEL
sudo yum install certbot python3-certbot-nginx
```

### 获取并自动配置证书

```bash
# 自动模式：Certbot 帮你修改 Nginx 配置
sudo certbot --nginx -d example.com -d www.example.com
```

执行后，Certbot 会：
1. 验证域名所有权
2. 从 Let's Encrypt 获取证书
3. 自动修改你的 Nginx 配置（添加 SSL 相关指令）
4. 设置自动续期任务

### 自动续期

```bash
# 测试续期是否正常
sudo certbot renew --dry-run

# 实际续期由 systemd timer / cron 自动执行
# 查看状态
sudo systemctl status certbot.timer
```

证书到期前 30 天内，certbot 会自动尝试续期。

## 手动配置 SSL（理解底层原理）

如果你用的是商业证书，或者想理解 Certbot 到底做了什么，这是手动配置：

### 第一步：获取证书文件

你最终会得到两个文件：
- **证书文件**（fullchain.pem）：你的证书 + 中间 CA 证书链
- **私钥文件**（privkey.pem）：**千万不要泄露！**

放在安全目录：
```bash
sudo mkdir -p /etc/nginx/ssl
sudo cp fullchain.pem /etc/nginx/ssl/example.com.pem
sudo cp privkey.pem /etc/nginx/ssl/example.com.key
sudo chmod 600 /etc/nginx/ssl/example.com.key  # 只有 root 能读
```

### 第二步：写 Nginx SSL 配置

```nginx
server {
    listen 443 ssl http2;
    server_name example.com www.example.com;

    ssl_certificate     /etc/nginx/ssl/example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/example.com.key;

    root /var/www/example;
    index index.html;
}
```

`http2` 参数是可选的，启用 HTTP/2 协议。但如果你的 Nginx 版本低于 1.25，需要用 `listen 443 ssl http2;`；1.25 及以上版本改为 `listen 443 ssl; http2 on;`。

### 第三步：HTTP 跳转到 HTTPS

```nginx
server {
    listen 80;
    server_name example.com www.example.com;

    # 把 HTTP 流量重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}
```

`301` 是永久重定向，浏览器会记住这个跳转，以后自动走 HTTPS。

## 生产级 SSL 参数

默认的 SSL 设置不够安全也不够快。你应该加上这些参数：

```nginx
# /etc/nginx/snippets/ssl-params.conf

ssl_protocols TLSv1.2 TLSv1.3;          # 禁用 TLS 1.0/1.1（不安全）
ssl_prefer_server_ciphers on;            # 由服务器决定加密套件

ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:
            ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;

# 启用 session 复用，减少重复握手的 CPU 开销
ssl_session_cache shared:SSL:10m;        # 10MB 约能存 40000 个 session
ssl_session_timeout 1h;
ssl_session_tickets off;                 # 禁用 session ticket（安全风险）

# DH 参数：增加密钥交换的安全性
ssl_dhparam /etc/nginx/ssl/dhparam.pem;

# OCSP Stapling：减少客户端验证证书的时间
ssl_stapling on;
ssl_stapling_verify on;
ssl_trusted_certificate /etc/nginx/ssl/example.com.pem;

resolver 8.8.8.8 8.8.4.4 valid=300s;
resolver_timeout 5s;
```

### 生成 DH 参数文件

```bash
# 这会花几分钟，因为它要生成一个很大的素数
sudo openssl dhparam -out /etc/nginx/ssl/dhparam.pem 2048
```

## HSTS：强制浏览器只用 HTTPS

HSTS（HTTP Strict Transport Security）告诉浏览器："以后访问这个域名，直接走 HTTPS，不要尝试 HTTP！"

```nginx
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;
```

| 参数 | 含义 |
|------|------|
| `max-age=63072000` | 2 年有效期 |
| `includeSubDomains` | 子域名也强制 HTTPS |
| `preload` | 可以提交到浏览器内置的 HSTS preload 列表 |

**注意**：一旦启用了 `includeSubDomains` 和 `preload`，你的域名就永久绑定了 HTTPS。如果某天你不想用 HTTPS 了，用户浏览器的 HSTS 记录会导致他们无法通过 HTTP 访问。谨慎使用。

## 完整的生产级 HTTPS 配置

```nginx
# /etc/nginx/conf.d/example.com.conf

# HTTP → HTTPS 跳转
server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;
}

# HTTPS 服务
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;
    server_name example.com www.example.com;

    # 证书
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # 安全参数
    include snippets/ssl-params.conf;

    # 安全响应头
    add_header Strict-Transport-Security "max-age=63072000" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;

    root /var/www/example;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

## 测试你的 SSL 配置

配完后用这些工具检查：

```bash
# 在线工具（推荐）
# SSL Labs: https://www.ssllabs.com/ssltest/

# 命令行检查
openssl s_client -connect example.com:443 -tls1_2
openssl s_client -connect example.com:443 -tls1_3

# 查看证书详情
echo | openssl s_client -connect example.com:443 2>/dev/null | openssl x509 -noout -dates -subject
```

目标：**SSL Labs 评分 A+**。

## 自签名证书（测试/内网用）

如果你只是测试或内网使用，不需要公信 CA 签发：

```bash
# 一步生成自签名证书（有效期 365 天）
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout /etc/nginx/ssl/selfsigned.key \
    -out /etc/nginx/ssl/selfsigned.crt \
    -subj "/CN=localhost"
```

浏览器会提示"不安全"，点击"高级→继续访问"即可。
