## 流量是好事，直到它变成攻击

你的网站突然涌入了大量请求。可能是上热搜了，也可能是有人在用脚本撞库。不管是哪种情况，你需要**限流（Rate Limiting）**来保护后端不被冲垮。

Nginx 提供两种限流机制：
- **`limit_req`**：按请求速率限流（每秒允许多少请求）
- **`limit_conn`**：按并发连接数限制（同时允许多少连接）

## limit_req：请求速率限制

```nginx
http {
    # 定义限流区域：$binary_remote_addr 是客户端 IP 的二进制形式
    # rate=10r/s 表示每秒允许 10 个请求
    limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s;

    server {
        location /api/ {
            # 应用限流
            limit_req zone=api_limit burst=20 nodelay;
            proxy_pass http://backend;
        }
    }
}
```

### 三个参数的含义

| 参数 | 含义 |
|------|------|
| `zone=api_limit` | 引用的限流区域 |
| `burst=20` | 突发允许的排队请求数 |
| `nodelay` | 排队的请求也立即处理（不延迟） |

**没有 `burst`**：超过 10r/s 的请求直接返回 503。
**有 `burst=20`**：前 20 个超额请求排队等待，再超过的返回 503。
**有 `burst=20 nodelay`**：前 20 个超额请求立即处理，再超过的返回 503。

`nodelay` 适用于 API——用户不希望你让他"等一会再处理"，要么立刻处理，要么拒绝。

### 实用场景

```nginx
# 登录接口：严格限流（防止暴力破解）
limit_req_zone $binary_remote_addr zone=login_limit:10m rate=1r/m;

location /api/login/ {
    limit_req zone=login_limit burst=3 nodelay;
    proxy_pass http://backend;
}

# 搜索接口：宽松限流
limit_req_zone $binary_remote_addr zone=search_limit:10m rate=30r/m;

location /api/search/ {
    limit_req zone=search_limit burst=10;
    proxy_pass http://backend;
}

# 全局 API：中等限流
limit_req_zone $binary_remote_addr zone=global_limit:10m rate=100r/s;

location /api/ {
    limit_req zone=global_limit burst=50 nodelay;
    limit_req_status 429;  # 返回 429 Too Many Requests 而不是 503
    proxy_pass http://backend;
}
```

### `$binary_remote_addr` vs `$remote_addr`

- `$remote_addr`：字符串形式的 IP（平均 ~15 字节）
- `$binary_remote_addr`：二进制形式的 IP（固定 4 字节 IPv4 / 16 字节 IPv6）

用 `$binary_remote_addr` 可以大幅节省共享内存。10MB 的 zone 如果用 `$remote_addr` 只能存约 6 万个 key，用 `$binary_remote_addr` 能存约 16 万个。

## limit_conn：并发连接数限制

防止一个 IP 同时开太多连接：

```nginx
http {
    limit_conn_zone $binary_remote_addr zone=conn_limit:10m;

    server {
        location /download/ {
            limit_conn conn_limit 5;  # 一个 IP 最多 5 个并发下载连接
            limit_conn_status 429;
            alias /var/www/files/;
        }
    }
}
```

常用于：
- 下载服务器：防止一个 IP 开 100 个线程下载
- 流媒体：防止盗链滥用

## 防盗链（Hotlink Protection）

有人把你的图片直接嵌入他的网站，消耗你的带宽。用 `valid_referers` 阻止：

```nginx
location ~* \.(jpg|jpeg|png|gif|webp)$ {
    valid_referers none blocked example.com *.example.com;
    if ($invalid_referer) {
        return 403;
    }
}
```

| Referer 值 | 含义 |
|------------|------|
| `none` | 没有 Referer 头（直接输入 URL） |
| `blocked` | Referer 存在但不合法（被防火墙/代理屏蔽） |
| `example.com` | 精确匹配域名 |
| `*.example.com` | 通配符匹配子域名 |

**注意**：部分浏览器为了隐私不发送 Referer 头。如果你设了 `valid_referers` 没包含 `none`，这些用户也会被拒。

## CORS 配置

当你的前端和后端不在同一个域名下时，浏览器会发 CORS 预检请求：

```nginx
location /api/ {
    # 允许的来源
    add_header Access-Control-Allow-Origin "https://app.example.com";

    # 允许的请求方法
    add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS";

    # 允许的请求头
    add_header Access-Control-Allow-Headers "Content-Type, Authorization";

    # 允许携带 Cookie
    add_header Access-Control-Allow-Credentials "true";

    # 预检请求缓存时间（秒）
    add_header Access-Control-Max-Age 86400;

    # OPTIONS 预检请求直接返回 204
    if ($request_method = 'OPTIONS') {
        return 204;
    }

    proxy_pass http://backend;
}
```

**`*` 不能与 `Credentials` 同时使用**。如果设了 `Allow-Credentials: true`，`Allow-Origin` 必须指定具体域名。

## 安全响应头

```nginx
# 防止点击劫持
add_header X-Frame-Options "SAMEORIGIN" always;

# 防止 MIME 类型嗅探
add_header X-Content-Type-Options "nosniff" always;

# 启用浏览器 XSS 过滤器
add_header X-XSS-Protection "1; mode=block" always;

# 推荐使用 CSP（内容安全策略）
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;" always;

# 禁止暴露服务器信息
server_tokens off;
```

`always` 关键字确保这些头在所有响应中都发送（包括错误页面）。

## 完整的生产级安全配置

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    # 不暴露 Nginx 版本
    server_tokens off;

    # 限制请求大小
    client_max_body_size 10m;
    client_body_buffer_size 128k;

    # 限制请求头大小（防止大 header DoS）
    large_client_header_buffers 4 32k;

    # 安全响应头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

    # 禁止访问隐藏文件
    location ~ /\. {
        deny all;
        access_log off;
        log_not_found off;
    }

    # 禁止直接访问敏感文件
    location ~* \.(bak|config|sql|fla|psd|ini|log|sh|inc|swp|dist)$ {
        deny all;
        access_log off;
        log_not_found off;
    }

    location /api/ {
        proxy_pass http://backend;
        include snippets/proxy-params.conf;
    }
}
```

## 小结

这一章我们学到了：

1. **limit_req** 做请求速率限制（rate + burst + nodelay）
2. **limit_conn** 做并发连接数限制
3. **防盗链** 用 `valid_referers` 阻止外部引用你的资源
4. **CORS** 配置跨域访问，注意 `*` 不能与 Credentials 共用
5. **安全响应头** 防止点击劫持、MIME 嗅探、XSS 等常见攻击
6. 隐藏 Nginx 版本、限制请求大小、禁止访问敏感文件
