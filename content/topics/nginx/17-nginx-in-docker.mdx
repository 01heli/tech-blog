## 为什么要在 Docker 里跑 Nginx？

你可能已经习惯在服务器上直接用 `apt install nginx`。但在以下场景中，Docker 化有明显优势：

- **环境一致性**：开发机、测试服务器、生产环境的 Nginx 版本完全相同
- **快速部署**：`docker compose up -d` 一条命令拉起整个技术栈
- **隔离**：不同项目的 Nginx 互不影响，版本可以不同
- **可移植**：换服务器就是复制 `docker-compose.yml` + 配置目录

## 最简单的 Nginx Docker

```bash
# 一行命令启动
docker run -d \
  --name nginx \
  -p 80:80 \
  -v /home/user/nginx/html:/usr/share/nginx/html:ro \
  nginx:1.25-alpine
```

访问 `http://localhost`，你就能看到 Nginx 的欢迎页。

**为什么用 alpine 版本？** Alpine Linux 是极小的 Linux 发行版（~5MB），Nginx Alpine 镜像只有约 20MB，而 Debian 版本约 140MB。

## 编写生产级 Dockerfile

对于生产环境，推荐自己写 Dockerfile 而非直接用官方镜像：

```dockerfile
# Dockerfile
FROM nginx:1.25-alpine

# 安装 envsubst（用于配置模板）
RUN apk add --no-cache gettext

# 删除默认配置
RUN rm -f /etc/nginx/nginx.conf /etc/nginx/conf.d/default.conf

# 复制配置文件（通过构建参数决定用哪个环境的配置）
COPY nginx.conf /etc/nginx/nginx.conf
COPY conf.d/ /etc/nginx/conf.d/
COPY snippets/ /etc/nginx/snippets/

# 创建缓存目录并设置权限
RUN mkdir -p /var/cache/nginx && \
    chown -R nginx:nginx /var/cache/nginx

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD wget --no-verbose --tries=1 --spider http://localhost/health || exit 1

EXPOSE 80 443

CMD ["nginx", "-g", "daemon off;"]
```

**关键点**：
- `nginx -g "daemon off;"`：Docker 容器必须前台运行，不能后台 daemon 化（否则容器立即退出）
- `HEALTHCHECK`：让 Docker 知道 Nginx 是否健康，配合编排工具自动重启

## 多环境配置模板

生产环境和测试环境的域名、后端地址可能不同。你可以用一个模板：

```nginx
# conf.d/app.conf.template
server {
    listen 80;
    server_name ${DOMAIN};

    location /api/ {
        proxy_pass ${BACKEND_URL};
    }
}
```

在 docker-entrypoint 中用环境变量替换：

```bash
#!/bin/sh
# docker-entrypoint.sh
# 在容器启动时，用环境变量替换模板中的 ${VAR}

for template in /etc/nginx/conf.d/*.template; do
    [ -f "$template" ] || continue
    envsubst '${DOMAIN} ${BACKEND_URL}' < "$template" > "${template%.template}.conf"
done

exec nginx -g 'daemon off;'
```

`envsubst` 只替换你指定的变量，不会动其他 `$nginx_var`。

## docker-compose：Nginx + 应用 + 数据库

```yaml
# docker-compose.yml
version: '3.8'

services:
  nginx:
    build:
      context: ./nginx
      dockerfile: Dockerfile
    container_name: nginx
    ports:
      - "80:80"
      - "443:443"
    volumes:
      # 挂载配置文件（方便热重载）
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      # 挂载 SSL 证书
      - ./nginx/certs:/etc/nginx/certs:ro
      # 挂载日志目录到宿主机
      - ./logs/nginx:/var/log/nginx
      # 挂载缓存目录
      - nginx_cache:/var/cache/nginx
    depends_on:
      - app
    restart: unless-stopped
    networks:
      - app_network

  app:
    image: node:20-alpine
    container_name: my_app
    working_dir: /app
    command: node server.js
    volumes:
      - ./app:/app
    expose:
      - "3000"
    restart: unless-stopped
    networks:
      - app_network

  db:
    image: mysql:8.0
    container_name: mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: myapp
    volumes:
      - db_data:/var/lib/mysql
    expose:
      - "3306"
    restart: unless-stopped
    networks:
      - app_network

volumes:
  db_data:
  nginx_cache:

networks:
  app_network:
    driver: bridge
```

### 关键细节

1. **Nginx 用 `ports`，后端用 `expose`**：`ports` 对外暴露，`expose` 只在 Docker 网络内可见。安全。

2. **volumes 挂载配置**：你可以在宿主机改 Nginx 配置，然后在容器内执行 `docker exec nginx nginx -s reload`，不需要重启容器。

3. **depends_on** 确保 Nginx 在应用启动之后再启动（虽然 `depends_on` 不等待应用 ready，但顺序对了可以避免启动时的连接错误）。

## 在 Docker 中热重载 Nginx

```bash
# 1. 修改宿主机上的配置文件
vim ./nginx/conf.d/app.conf

# 2. 测试配置
docker exec nginx nginx -t

# 3. 热重载
docker exec nginx nginx -s reload
```

如果配置没问题，你不会看到任何请求中断。

## 日志管理

Docker 容器内的日志有两个去处：

### 方式 1：输出到 stdout（推荐）

```nginx
# nginx.conf
access_log /dev/stdout;
error_log /dev/stderr warn;
```

这样日志进入 Docker 的日志系统，可以用 `docker logs nginx` 查看：

```bash
docker logs -f nginx                          # 实时跟踪
docker logs --tail=100 nginx                  # 看最后 100 行
docker logs --since=10m nginx                 # 最近 10 分钟的日志
```

### 方式 2：写入文件 + volume 挂载

```nginx
access_log /var/log/nginx/access.log main;
```

配合前面的 `docker-compose.yml` 中 `- ./logs/nginx:/var/log/nginx`，日志就写到了宿主机。

## 常见 Docker 问题

### Nginx 启动后容器立即退出

检查 `CMD` 指令：
```dockerfile
CMD ["nginx", "-g", "daemon off;"]   # ✅ 前台运行
CMD ["nginx"]                          # ❌ 默认后台 daemon，容器退出
```

### 502 Bad Gateway（连不上后端）

在 Docker 网络中，`localhost` 指的是容器自己，不是宿主机。访问同 compose 中的另一个服务要用**服务名**：

```nginx
# ❌ 错的
proxy_pass http://127.0.0.1:3000;

# ✅ 对的（app 是 compose 中的服务名）
proxy_pass http://app:3000;
```

### 静态文件权限问题

确保 Nginx 用户（通常是 `nginx` 或 `101`）有读取挂载文件的权限：

```dockerfile
RUN chown -R nginx:nginx /usr/share/nginx/html
```
