## 2026-06-03 23:58:59

- **第 8 步收尾：示例数据 + CLI 可用性验证** — 项目代码全部就绪但缺少可构建的文档，我运行 `/build data/` 才发现 `data/` 目录还不存在。创建 `data/` 目录并放入 3 篇中文技术文档（RAG 简介、向量检索详解、本地大模型部署指南），覆盖知识库核心知识点，构建后知识库能回答 RAG 相关问题。

- **模型自动检测与智能切换机制** — 这是今天最大的改进点。LM Studio 只能加载一个模型，每次问答需切换两次（BGE-M3 检索 → Qwen 生成 → 切回 BGE-M3 等下一问）。之前 `step7_cli.py` 只打印一句"请确保已加载 XXX"，不检查模型是否真的切换了，模型不对就静默报错。我做了三步改进：
  1. `_get_current_model()` — 调 `/v1/models` 端点获取当前加载的模型 ID，加 5 秒缓存避免频繁请求
  2. `_is_embedding_model()` / `_is_chat_model()` — 用模型名关键词（embed/bge/qwen 等）判断类型，无需维护白名单
  3. `_ensure_model(target)` — 检测 → 不对就暂停，打印三步操作指引（停止当前→加载目标→确认 Server 启动），等我按 Enter 后再继续
  - 同时新增 `/models` 命令随时查看当前模型，`/status` 中显示当前模型，帮助文本同步更新

- **dev-log skill 规范增强** — 更新 `.claude/skills/dev-log.md`，明确每条日志要点必须覆盖三点：在之前基础上新完成了什么 → 怎么实现、用了什么方法 → 注意事项/遇到的问题及解决方式。示例也从原来的两行摘要式重写为体现三点结构的完整条目，同时加了"语言干净不拖沓，禁废话和装饰性用词"的硬约束

- **改进体验**：之前我切到 Qwen 后想提问，问题无法被向量化（因为 Qwen 不是嵌入模型），只能看到报错；现在程序主动告诉我"当前是 Qwen，需要切回 BGE-M3 做检索，按 Enter 继续"，不再盲目调用 API

- **一口气推进 4 步（第 3~6 步）** — 从文本分块器到 RAG 管线全部串联跑通
  - **第 3 步 `step3_chunker.py`**：纯 Python 实现文本分块器，核心是 `find_split_point()`——在目标位置附近找最自然的语义断点（优先级：句号 > 换行 > 逗号 > 空格 > 硬切），保证不会在句子中间切一刀。`_advance_by_tokens()` 和 `_rewind_by_tokens()` 两个辅助函数做"字符索引 [X] token 数"的近似映射，中文按字计、英文按单词计
  - **第 4 步 `step4_vectorstore.py`**：两个 list（`_chunks` + `_vectors`）实现向量库，`search()` 暴搜所有向量算余弦相似度然后排序取 top_k，`save()/load()` 用 JSON 持久化——数据透明，文本编辑器就能看
  - **第 5 步 `step5_loader.py`**：文档加载器，支持 txt/md/pdf 三种格式。Markdown 加载时剥离 YAML frontmatter（只认文件开头的 `---` 对），正文中的 `---` 分割线不动。编码用 utf-8 优先 + gbk 回退（Windows 中文文档常见）。单个文件损坏不连累其他文件
  - **第 6 步 `step6_rag_pipeline.py`**：把前 5 步串成两个命令——`build`（建库）和 `ask`（问答）。提示词设计上，每个资料块标注 `[来源: 文件名]` 实现可溯源，明确要求 LLM "不知道就说不知道"防止幻觉
  - 编写了完整的 [README.md](https://github.com/01heli/local-rag-knowledge-base)，包含数据流 ASCII 图、8 步路线图（带完成标记）、环境准备说明

- **遇到问题：step2 无法被 import**
  - step2 的 `client = OpenAI(...)` 和 `response = client.embeddings.create(...)` 写在模块顶层，没有 `if __name__ == "__main__"` 保护
  - 导致 `from step2_embedding import cosine_similarity` 时会立刻发起 HTTP 请求——如果 LM Studio 没启动，import 就报错
  - 解决：把 API 调用代码全部移到 `if __name__ == "__main__":` 里面，模块顶层只留纯函数定义。第 4、6 步正是依赖这个修复才能安全复用 step2 的函数

- **遇到问题：中文引号与 Python 字符串冲突**
  - 测试文本中的 `"参考资料"`（中文全角双引号 U+201C/U+201D）被文件系统/工具链自动转换成了 ASCII 半角引号 `"`
  - Python 解析器把转换后的 `"` 当作字符串结束符，导致 `SyntaxError`
  - 解决：外层用单引号 `'...'` 包裹，内部的中文引号就不会冲突

- **遇到问题：极端小 chunk_size 下出现碎片 chunk**
  - 测试时 chunk_size=80（刻意的小值），某些短句被单独切成一个 20 token 的碎片 chunk——因为 `find_split_point` 找到句号后立即切分，没有检查 chunk 是否太小
  - 解决：在 `chunk_text` 中增加最小 chunk 保护——如果切出来的 chunk 比 overlap 还短，往后推到下一个断点再切，保证每个 chunk 至少比重叠区长

- **遇到问题：LM Studio 单模型限制**
  - 建库需要 BGE-M3（嵌入），问答既需要 BGE-M3（嵌入问题）又需要 Qwen（生成回答），但 LM Studio 同一时间只能加载一个模型
  - 解决：`ask` 命令内部拆成两段——先用 BGE-M3 做检索，再提示用户切换到 Qwen 生成回答。如果 Qwen 没加载，不静默失败，而是打印完整提示词让用户手动复制发给模型

- **第 2 步：嵌入接口 + 余弦相似度** — 编写 `step2_embedding.py`，掌握文本转向量和语义相似度计算
  - **练习 A**：调用 `client.embeddings.create()`，传入 `"苹果是一种水果"`，拿到 768 维向量
  - **练习 B**：不用 NumPy，纯 Python 实现 `dot_product()` / `magnitude()` / `cosine_similarity()` 三个函数，自测向量自身的相似度为 `1.0`
  - **练习 C — 语义相似度对比**：

    **BGE-M3（中文嵌入模型）——最终结果：**

    | 文本 A | 文本 B | 相似度 | 结论 |
    |--------|--------|--------|------|
    | 苹果很好吃 | 香蕉很好吃 | 0.8004 | 高 — 同主题（水果 + 口感） |
    | 苹果很好吃 | 苹果是一种水果 | 0.8290 | 高 — 同一对象（苹果） |
    | 苹果很好吃 | 今天天气不错 | 0.6144 | 低 — 完全不相关 |

  - **遇到问题 1 — 英文嵌入模型对中文无效**：最初使用 `nomic-embed-text-v1.5`（英文原生模型），跑同样的三组对比，所有相似度全部挤在 0.73~0.78 之间，根本分不清哪组相关哪组不相关：

    **nomic-embed-text-v1.5（英文模型）——失败结果：**

    | 文本 A | 文本 B | 相似度 | 结论 |
    |--------|--------|--------|------|
    | 苹果很好吃 | 香蕉很好吃 | 0.7822 | 无法区分 |
    | 苹果很好吃 | 苹果是一种水果 | 0.7306 | 无法区分 |
    | 苹果很好吃 | 今天天气不错 | 0.7532 | 无法区分 |

    原因：英文模型没有中文语义表征能力，对中文文本只能捕捉到浅层字符级特征。解决：替换为支持中文的 **BGE-M3** 嵌入模型，分数立即拉开差距（最低 0.61 vs 最高 0.83，跨度为 0.22）

  - **遇到问题 2 — LM Studio 无法同时运行两个模型**：同一时间只能加载一个模型到 Server。现阶段影响不大（分步操作），后续做 RAG 管线串联时需要考虑双实例方案
